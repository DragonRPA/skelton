# [발상] 엑셀 파싱 시 하드코딩 인덱스 대신 동적 헤더 매핑 도입

- **타임스탬프**: 2026-09-01 17:20
- **맥락**: 엑셀 업로드 시 `r[1]`, `r[2]`와 같이 열 위치(Index)를 하드코딩해 두었더니, 현업 엑셀 원본에 "연번" 같은 열이 하나 추가되거나 열 순서가 바뀌는 순간 모든 데이터 매핑이 연쇄적으로 어긋나는 장애가 연속 발생함.
- **핵심 내용**: 
  - 하드코딩 탈피: 파일을 읽을 때 텍스트 헤더 행을 먼저 스캔하여 `{"현장명": 2, "모델명": 3, "월렌탈료": 22}` 형태의 인덱스 매핑(Map)을 동적으로 구성한다.
  - 동적 참조: 이후 데이터 행을 파싱할 때 `r[2]` 대신 `r[headerMap.get("현장명")]` 방식으로 값을 추출한다.
  - 효과: 현업 담당자가 엑셀 중간에 임의로 메모 열을 추가하거나 순서를 섞더라도 시스템이 절대 깨지지 않는 강력한 유연성과 내구성을 확보할 수 있다.
- **상태**: 논의 및 계획 대기 중
