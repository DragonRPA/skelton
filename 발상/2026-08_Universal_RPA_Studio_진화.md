## 발상 1: Keep 리스트 기반 자연어 프롬프트 빌더

> "셀렉트 된 객체를 keep 해서, 변수처럼 사용하게 해서 문장을 작성해서 자연어 프롬프트를 완성하면 한번에 쉽게 RPA 자동화 스크립트를 AI에게 작성 가능하도록 지시할수 있지 않을까?"

DOM에서 찾은 요소를 `{변수명}` 형태로 보관하고,
자연어 지시문 작성 시 `{변수명}`을 변수처럼 삽입하면
AI가 `{변수명}=셀렉터` 매핑을 참조해서 Playwright 코드를 정확하게 생성한다.

### 핵심 인사이트
- 기존: DOM 수집 → 셀렉터 복사 → 수동 코드 작성
- 개선: DOM 수집 → Keep → {변수} → 자연어 → AI 코드 자동 생성
- {변수명} 패턴이 AI와 인간 모두에게 직관적인 인터페이스가 된다

## 발상 2: 요소 타입별 액션 자동 제안

> "킵된 객체를 선택했을 때, 이 객체를 어떻게 조작할 수 있는지 미리 알 수 있지 않나?"

element_type 기반으로 가능한 조작을 자동 분류:
- `input` → 값 입력, 내용 지우기, 현재 값 확인
- `button` → 클릭, 더블클릭, 마우스 오버, 활성화 확인
- `select` → 옵션 선택, 현재 값 확인, 전체 옵션 수집
- `checkbox` → 체크, 체크 해제, 상태 확인
- `table` → 데이터 추출, 행 수 확인, 특정 행 클릭

선택하면 자연어 문장 조각이 커서 위치에 자동 삽입된다.

### 핵심 인사이트
- UI 요소의 타입 정보가 곧 RPA 액션의 메타데이터다
- element_type → Playwright method 의 자동 매핑이 핵심

## 발상 3: 데이터 소스 배치 처리 패러다임

> "RPA는 주로 엑셀이나 CSV나 JSON 같은 배열 구조를 가지는 데이터를 입력 받아서 반복적으로 처리하는 유형이 많아"

Excel/CSV/JSON 파일의 컬럼을 `{row.컬럼명}` 변수로 자동 등록하고,
AI 프롬프트에 데이터 소스 컨텍스트를 자동 포함시키면
AI가 pandas + Playwright 루프 스크립트를 자동 생성한다.

### 핵심 인사이트
- RPA의 80%는 "데이터 × 반복" 패턴이다
- 데이터 소스가 있으면 AI는 자동으로 루프 구조를 선택해야 한다
- `{row.컬럼명}` 칩이 `{Keep변수}` 칩과 나란히 배치되는 UX가 자연스럽다

## 발상 4: 프로젝트 중심 RPA 개발 도구

> "앞으로 프로젝트를 생성하고, 프로젝트 단위에서 여러 URL, Keep 요소, 스크립트를 관리하고 DB에 저장하기를 원해"

5개 테이블 관계형 스키마:
`rpa_projects → rpa_targets → rpa_keep_elements → rpa_tasks ↔ rpa_task_elements`

앱 시작 시 프로젝트 선택 모달, 생성된 스크립트마다 지문(Fingerprint) 자동 삽입,
DEBUG/RELEASE 빌드 타입 구분으로 운영 배포 이력 관리.

### 핵심 인사이트
- RPA 스크립트도 소프트웨어다. 버전/환경/작성자 추적이 필수
- 지문 헤더는 스크립트 파일 하나만 봐도 모든 맥락을 알 수 있게 한다
- 프로젝트 개념이 없으면 Keep/스크립트가 세션 종료 시 사라진다
