## 1. 발상 배경 및 문제의식

1. **대규모 코드베이스(650+ 파일, 50만+ 라인) 수정·최적화 시 맥락 손실 문제**:
   - 파일 수가 수백 개에 달하면 수정 착수 전 매번 전체 디렉터리를 재탐색하느라 컨텍스트 윈도우가 소진되고, 역참조(`importedBy`) 영향 범위나 PC↔모바일 대칭 파일 누락·중복 유틸 신설이 발생한다.
2. **수작업 문서화의 즉시 부패(Stale Doc) 방지**:
   - 사람이 손으로 적은 파일 목록 문서는 파일 분할·추가·삭제가 일어나는 즉시 현실 코드와 괴리된다. TypeScript 컴파일러 AST와 다중 언어 파서로 의존성·규모·메뉴 매핑을 자동 추출하고, `--verify` 게이트로 불일치 시 즉시 실패하도록 강제해야 문서가 살아있는 SSOT가 된다.
3. **글로벌 규칙 파일 24KB 인라인 절단 함정 해결**:
   - Antigravity 규칙 로더는 단일 규칙 파일의 상위 24,000바이트까지만 컨텍스트에 직접 인라인하고 이후는 절단한다. 따라서 글로벌 정책 추가 시 하단 `[카테고리 XV]`에만 적으면 에이전트 초기 턴에 노출되지 않으므로, 반드시 상위 24KB 이내인 `[카테고리 I]` 내부(`1.5`조 / `1.7`조)에 핵심 의무를 배치하고 하단에 상세 실행 규격을 두는 2단 구조를 채택한다.

## 2. 핵심 설계 구상

1. **AST 기반 명세 생성·검증·질의 3단 CLI (`scripts/generate_code_file_spec.cjs` + `scripts/code_file_descriptions.cjs`)**:
   - `npm run spec:sync`: 활성 코드 파일(14대 계층) 전수 스캔, 정·역방향 AST 의존성(`Out`/`Fan-In`), DB 접근 테이블, PC↔모바일 19대 대칭 쌍, 5대 최적화 시그널을 산출해 `docs/CODE_FILE_SPECIFICATION.md`와 `docs/code_file_manifest.json` 생성.
   - `npm run spec:verify`: 디스크 실파일과 매니페스트·명세서 1:1 정합성 및 미기재 설명 `0건` 검증.
   - `npm run spec:query -- <검색어>`: 파일명·`menuId`·Export 심볼·DB 테이블·최적화 플래그 기준 즉시 영향도 조회.
2. **글로벌 5대 최적화 정량 기준**:
   - ① `GOD_FILE`(1,500줄/80KB 초과) 분할, ② PC↔모바일 대칭 쌍 및 다중 페이지 중복 로직 단일화, ③ `EAGER_ROUTE_IMPORT` 정적 페이지의 `React.lazy()` 전환, ④ `HIGH_COUPLING_HUB`(`Fan-In >= 8`) 연쇄 영향 차단, ⑤ `ORPHAN_CANDIDATE`(`Fan-In = 0`) 실사 정리.
3. **배포 번들 격리 원칙**:
   - 명세서 및 매니페스트 JSON은 `public/`이 아닌 `docs/` 하위에 두어 프로덕션 `dist/` 정적 번들에 포함되지 않도록 분리한다.
