## 1. 발상 배경 및 사장님 핵심 화두 (Inception Context)

> **"1단어(용어) 1뜻 정의를 개발과 프로젝트 진행 과정에서의 효익으로 생각하고, 전체 프로젝트에 적용하라."**

소프트웨어 개발과 프로젝트 지연의 대부분은 코딩 기술의 부족이 아니라, **'동일한 대상을 서로 다른 단어로 부르는 동의어 파편화'**와 **'서로 다른 업무를 하나의 단어로 뭉뚱그리는 다의어의 혼란'**에서 비롯된다.

'배차'와 '출고', '교환'과 '대차'가 혼용될 때마다 기획자, 개발자, 회계담당자, 그리고 AI 에이전트는 끊임없는 인지적 번역 비용(Cognitive Translation Cost)을 치러야 하며, 이는 곧 DB 컬럼 파편화, 불필요한 어댑터 코드 양산, 회계적 불일치로 이어진다.

## 2. 격상된 본질 목표 (Elevated Core Teleology)

> **"언어의 다의성(모호함)을 박멸하여 프로젝트 엔트로피를 $O(1)$로 수렴시키고,**  
> **[기획 ➔ DB 스키마 ➔ API ➔ 프론트 UI ➔ 회계 ➔ AI 프롬프트]까지**  
> **단 하나의 고유 명사·동사가 1:1로 관통하는 단일 진실의 원천(Semantic SSOT)을 확립한다."**

## 3. 4대 계층 핵심 효익 (4-Tier Structural Benefits)

1. **소프트웨어 및 DB 계층**:
   - 변수명, API 엔드포인트, DB 컬럼명, 프론트엔드 타입이 동일 단어로 일치.
   - 단어를 변환하고 매핑하는 불필요한 번역 계층(Glue Code) 수백 줄 삭제.
2. **비즈니스 및 회계 계층**:
   - 업무 R&R과 법적·회계적 책임 경계선이 명확화 (예: 영업의 `대차 의뢰` vs 자산팀의 `출고 매핑`, 단일 `EXCHANGE` 배차).
   - "그게 그 뜻이었냐"는 소통 회의와 확인 절차 80% 이상 소멸.
3. **UI/UX 인터페이스 계층**:
   - 단어 자체에 물리적 사건이 100% 압축되어 있으므로, 불필요한 미사여구와 수식어 덧칠 없이 건조한 명사·동사만으로도 오독이 없는 최고 밀도 화면(헌장 3.1) 구현.
4. **AI-Native 에이전트 계층**:
   - LLM 프롬프트의 의미적 모호성이 제거되어, 환각(Hallucination) 및 엉뚱한 테이블 조인/상태 오판 0% 달성.

## 4. 다의어·동의어 파편화 3대 금지 패턴

1. **동의어 파편화 금지**: 동일한 대상을 부서나 개발자 편의에 따라 여러 단어로 분기하는 행위 금지 (`'EXCHANGE'` 단일 표준 등).
2. **다의어 포괄 호칭 금지**: 물리적 사건과 책임 주체가 상이한 다단계 프로세스를 하나의 두루뭉술한 단어로 퉁치는 행위 금지 (`배차` vs `출고`).
3. **수식어 덧칠(Cruft) 방지**: 단어의 뜻이 불분명하여 앞에 감성적·과장적 수식어('진짜 출고', '최종 확정 배차')를 붙이는 행위를 일절 금지.
