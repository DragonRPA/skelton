## 1. 발상 배경 및 사장님의 핵심 구상 (Core Concept)

> **"사전에 정의한 계약 및 출고의뢰 양식의 google gemini GEMS 를 정의하고, 회수의뢰, 교환의뢰 등등 각종 업무서식을 완성해주고 누락정보를 교차검증 해주도록 한 뒤에 GEMS 로부터 데이터를 전달받아서 ERP 시스템에서 작동되게 하는 아이디어는 구현이 가능할 까? 만약 그렇다면 영업사원은 음성으로 젬스를 호출하기만 하면 될것도 같은데?"**
> — 이수용 사장님 (2026-09-04)

### 🎯 사장님 구상의 본질적 가치
1. **단순 입력을 넘은 '지능형 교차검증(Cross-Verification)'**:
   - 영업사원의 발화 중 필수 항목(현장주소, 단가조건, 현장담당자 연락처, 교환 시 전자산 번호 등)이 빠져 있으면 AI가 스스로 알아채고 되물어 서식을 완벽히 메움.
2. **다양한 업무서식의 단일 창구화 (Omni-Form Voice Portal)**:
   - 출고의뢰뿐만 아니라 **회수의뢰**, **교환(대차)의뢰**, **계약변경의뢰**까지 음성 하나로 분류·처리.
3. **ERP 시스템과의 완벽한 데이터 직결 (Automated DB Ingestion)**:
   - AI와의 음성 대화가 끝나면 사람이 다시 복사/붙여넣기할 필요 없이, ERP 배차/계약/정비 대장에 실데이터로 다이렉트 꽂히는 무결성 달성.

## 2. 기술적 구현 가능성 및 2대 아키텍처 비교

### 🔍 [분석 1] Google 공식 Gemini 앱 내의 'Gems' 직접 연동 한계
- 구글 Gemini 웹/앱의 Gems 기능은 텍스트/음성 대화에는 훌륭하지만, **Gems에서 사내 사설 ERP(Supabase/Vercel)로 데이터를 자동 발송하는 아웃바운드 웹훅(Webhook) 기능이 공식 제공되지 않음**.
- 따라서 일반 Gems를 그대로 쓰면 대화 완료 후 생성된 JSON을 영업사원이 손으로 복사하거나 확인 버튼을 눌러야 하는 매개 단계가 발생함.

### 🚀 [분석 2] 해결책 — Gemini API Function Calling 기반 '기연 인앱 전용 GEMS (In-App Agent)'
- **구글 Gemini 1.5 Flash/Pro의 Tool Calling (함수 호출) 아키텍처 활용**:
  - GEMS의 시스템 프롬프트(지식/규칙/서식 검증)를 Gemini API에 주입.
  - 여기에 ERP 연동 함수(`submitDispatchOrder`, `submitReturnOrder`, `submitExchangeOrder`)를 도구(Tool)로 등록.
  - **작동 흐름**:
    1. 영업사원 음성 발화 (모바일 웹앱 또는 음성 숏컷).
    2. Gemini가 대화하면서 누락 항목을 질문하고 서식을 100% 완성.
    3. 조건 충족 즉시 Gemini가 `submitDispatchOrder({ ... })` 함수를 스스로 실행.
    4. Supabase DB에 실시간 저장 완료 및 배차 담당자에게 알림 발송!

## 3. 지원 가능한 4대 핵심 업무서식 정의

1. **출고의뢰 (Dispatch Order)**:
   - 고객사, 현장, 납품일시, 장비모델/수량, 현장담당자/연락처, 보양/옵션.
2. **회수의뢰 (Return Order)**:
   - 계약번호 또는 현장명, 회수 대상 자산번호, 회수 희망일시, 현장 반출 담당자.
3. **교환/대차의뢰 (Exchange Order - 헌장 2.3)**:
   - 교체 사유(고장/규격변경), 회수할 전자산 번호, 투입할 후장비 요구스펙, 왕복 배차('EXCHANGE') 1건 자동 발행.
4. **현장AS 접수 (Field AS Intake)**:
   - 장비번호, 고장 증상, 긴급도, 현장 위치.

## 4. 기대 효과 (System Core Mission)
- **영업사원의 조작 노력 = 0**: 타이핑 제로, 순수 음성 질의응답으로 업무 완결.
- **부서 R&R 엄격 준수 (헌장 2.1)**: 영업사원은 요구만 음성으로 전송하고, 출고/자산 부서가 자산을 배정하는 프로세스 자동화.
- **데이터 무누락 저장 (헌장 1.2)**: 누락된 필드를 AI가 반드시 캐치하여 물어보므로 불완전한 접수 원천 차단.
