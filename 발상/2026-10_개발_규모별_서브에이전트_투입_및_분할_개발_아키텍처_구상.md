## 1. 발상 배경 및 사장님 핵심 화두 (Inception Context)

> **"개발 규모에 따라서 서브에이전트를 투입하여 분할개발을 진행하라."**

AI 에이전트와 페어 프로그래밍을 진행할 때, 모든 작업을 메인 에이전트 혼자서 장기적으로 끌고 가면 컨텍스트 윈도우가 급격히 비대해져 앞단의 설계 원칙을 잊어버리는 **컨텍스트 표류(Context Drift)**와 개발 지연이 발생한다.
반대로 한 줄 버그 수정이나 단순한 텍스트 변경에 무조건 서브에이전트를 띄우면 통신 오버헤드와 자원 낭비가 발생한다.

따라서 **작업의 본질적 규모(Scope & Complexity)를 사전에 명확히 진단하고, 이에 최적화된 서브에이전트 팀을 구성하여 병렬 분할 개발을 집행하는 적응형 오케스트레이션 체계**가 필수적이다.

## 2. 격상된 본질 목표 (Elevated Core Teleology)

> **"작업 규모에 따른 3단계(소/중/대) 적응형 분할을 통해 컨텍스트 오염을 원천 차단하고,**  
> **[타입 선행 ➔ 파일 격리 ➔ 비동기 병렬화 ➔ 종단 통합 검증] 4대 원칙을 통해**  
> **개발 속도를 3배 이상 단축하면서 100% 무결점을 보장하는 분할 개발 파이프라인을 확립한다."**

---

## 3. 개발 규모 3단계 매트릭스

1. **소규모 (Small)**:
   - 단일 파일 수정, 버그 패치, 단순 컴포넌트/스타일 수정 (영향 범위 1~2개 파일).
   - ➔ **메인 에이전트 단독 수행** (오버헤드 0ms 달성).
2. **중규모 (Medium)**:
   - 1개 기능의 프론트 + 백엔드 + DB 연동, 3~5개 파일 리팩토링.
   - ➔ **1~2개 전문 서브에이전트 투입** (Backend/DB 에이전트에게 구현 위임 후 메인 에이전트와 협업).
3. **대규모 (Large)**:
   - 신규 메뉴/페이지/시스템 전면 구축, 멀티 탭 비즈니스 로직, WTT 관통 스트레스 테스트.
   - ➔ **오케스트레이터(메인) + 3인 이상 서브에이전트 팀 구성** (PM ➔ Backend ➔ Frontend ➔ Auditor).

---

## 4. 분할 개발 4대 불변 원칙

1. **타입/인터페이스 선행 확립 (Contract-First)**: 입출력 인터페이스와 DB 스키마를 먼저 확정하여 에이전트 간 불일치 방지.
2. **원자적 파일 경계 격리 (Atomic File Boundary)**: 서브에이전트 간 파일 쓰기 충돌 방지를 위해 상호 배타적 파일/폴더 권한 할당.
3. **비동기 자율 병렬화 (Parallel Dispatch)**: 상호 의존성 없는 모듈은 `invoke_subagent`로 동시 발주.
4. **종단 통합 검증 의무화 (Integration Audit)**: 분할 작업 완료 후 메인 에이전트가 빌드·린트·타입체크를 실행하여 최종 승인.
