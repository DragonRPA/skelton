# 복잡 업무 프로세스 — 사전 인터뷰 설계 방법론

> 기록일시: 2026-08-30 14:10  
> 발견 맥락: 기연리프트 청구 업무 프로세스 설계 중 자연스럽게 창안

---

## 💡 발상의 핵심

> **"복잡한 업무 프로세스를 코드로 구현하기 전에,  
> 모든 엣지케이스를 선제적으로 발굴하여  
> 구조화된 질문으로 전수 파악하는 인터뷰 방법론"**

---

## 기존 방식의 문제

일반적인 개발 사이클:
```
요구사항 청취(단순) → 코딩 → 테스트 중 엣지케이스 발견 → 재코딩 → 반복
```

이로 인해:
- 동일 기능을 3회 이상 반복 개편하는 악순환 발생
- 실무자와 개발자 간 "말이 달랐다"는 책임 소재 불명확
- 설계 결함이 코드 깊숙이 박혀 기술부채로 굳어짐

---

## 이 방법론의 구조

### 1단계: 엣지케이스 사전 발굴
해당 업무의 **가장 복잡한 케이스**를 기준으로 질문 목록을 먼저 설계.  
"평균적인 케이스"가 아닌 **예외 상황**을 중심으로 질문을 구성.

### 2단계: 섹션 분류
질문을 업무 흐름의 단계별로 섹션화:
```
예: 청구 업무의 경우
A. 기준 기간 정의
B. 계산 원칙
C. 예외 상황 1 (자산 교체)
D. 예외 상황 2 (계약 변동)
E. 고객 복합 케이스
F. 문서 흐름
G. 세금/규제
H. 부대 발생
I. 수납/정산
J. 취소/수정
```

### 3단계: 선택지 방식 질문
각 질문에 번호형 선택지(1/2/3/4) + 기타(직접 설명) 제공.
- 선택지는 실무에서 실제로 발생하는 패턴만 수록
- "기타"를 선택하면 파생 질문이 즉시 생성됨

### 4단계: 파생 질문 즉시 생성
답변이 예상 범위를 벗어나면 그 자리에서 파생 질문 추가.  
예: D-3 "단가 변경 시 청구 처리" → 답변이 "기간 중간 변경 안 함"이라는 새 규칙  
→ 즉시 D-3a "소급 변경 시 기존 청구 처리" 파생 질문 생성

### 5단계: 설계 문서 자동 생성
인터뷰 완료 후 Q&A 전체를 원칙 문서로 자동 변환.  
이 문서가 **개발 착수의 공식 근거**가 됨.

---

## 적용 효과 (청구 업무 사례)

- 인터뷰 소요: 약 30분
- 발굴된 엣지케이스: 12개 이상
  - 소급 단가 변경 처리
  - 거래명세서 표기명 이원화 (내부/고객용 분리)
  - 외상미수금 분할 청산 관리
  - 비환불 케이스 입금잔액 잔류 처리
  - billingDay 월말 초과 자동 처리
  - 교체 당일 귀속 원칙
  - 연체이자 0% 기본값 설계
  - 납기일 계약별 개별 지정 등
- **스키마 보완 사항 4개** 사전 발굴 (개발 후 발견 시 대규모 리팩토링 필요했을 항목)

## 실무자 재수행 가이드

### AI와 함께 (권장)
- 실무자가 AI와 1:1 인터뷰 형식으로 진행
- AI가 파생 질문을 실시간 생성하는 것이 핵심 가치
- 슬래시 명령 `/grill-me` 활용 가능

### 독립 수행 (문서 전달)
- 인터뷰 명세서를 실무자에게 전달하여 자가 답변
- 선택지 해석 오류 가능성 있으므로 검토 세션 필요
