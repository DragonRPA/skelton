# 시선과 업무 동선 일치 Z-패턴 UI/UX 표준 (Gutenberg Workflow Standard)

> **기록 일시**: 2026-09-02 19:12

> **관련 프로젝트**: DragonRPA ERP, Kiyeun Lift, Universal RPA Studio

## 1. 발상 배경 (Background)
전문 관리 시스템 및 ERP 화면에서 조회 조건(필터), 데이터 유입(엑셀 업로드), 데이터 검증(테이블/그리드), 최종 완결 액션(결재/지급요청/저장)이 화면 곳곳에 무질서하게 배치되면 다음과 같은 치명적 비효율이 발생한다:
1. **시선 역류 (Reverse-Flow)**: 하단에서 데이터를 검토한 뒤 다시 상단이나 중앙으로 올라가서 버튼을 찾는 인지 부하.
2. **조작 패널 과다로 인한 본문 위축**: 상단에 버튼과 카드가 3~4줄로 쌓여 정작 중요한 메인 검증 작업대 공간이 50% 미만으로 축소되는 현상.
3. **실무 집중도 저하**: 작업 순서(필터 ➔ 입력 ➔ 검증 ➔ 완결)와 시선의 자연스러운 이동 방향이 불일치하여 발생하는 조작 피로.

## 2. 4단계 Z-패턴 직무 완결 동선 법칙 (Gutenberg Workflow Law)

인간공학적 시선 흐름인 **구텐베르크 다이어그램(Gutenberg Diagram)** 및 **Z-패턴**을 엔터프라이즈 업무 라이프사이클에 1:1로 일치시킨다.

```
┌───────────────────────────────────────────────────────────────────────────────────┐
│ ① [좌측 상단 (Start/Scope)]                     ② [우측 상단 (Input/Pipeline)]     │
│   • 조회 기간, 거래처, 대상 필터                  • 엑셀 업로드, 양식 다운, 조회 실행   │
│   (업무의 시작 조건 설정)                         (데이터 유입 및 파이프라인 트리거)   │
├───────────────────────────────────────────────────────────────────────────────────┤
│                                                                                   │
│ ③ [중앙 본문 (Body/Inspection) - 화면의 85% 고밀도 확보]                           │
│   • 좌우 1:1 대사 작업대, 데이터 그리드 테이블                                    │
│   • 일치/불일치 항목 검토, 인라인 차액 승인, 예외 처리                             │
│   (데이터 정합성 분석 및 1차 검증)                                                │
│                                                                                   │
├───────────────────────────────────────────────────────────────────────────────────┤
│                                                 ④ [우측 하단 (Terminal Action)]    │
│   • 대차대조 합계 (차액 ₩0 증명)                  • [최종 매입 지급요청], [일괄 승인] │
│                                                   (업무의 최종 종결 및 저장)          │
└───────────────────────────────────────────────────────────────────────────────────┘
```

### 4단계 동선 세부 원칙
1. **① 좌측 상단 (Start / Scope)**: 업무의 대상과 범위를 좁히는 필터가 위치한다. (기간, 거래처, 지점 등)
2. **② 우측 상단 (Input / Pipeline)**: 외부 데이터를 유입시키거나 조회를 트리거하는 액션 버튼이 위치한다. (엑셀 업로드, 양식 다운로드, 검색 버튼)
3. **③ 중앙 본문 (Body / Inspection)**: 화면 높이의 80~85%를 차지하는 고밀도 그리드. 사용자가 위아래 스크롤을 최소화하며 데이터를 1:1로 검증한다.
4. **④ 우측 하단 (Terminal Action / Final Execution)**: 모든 검증과 대사가 완료되었을 때 최종적으로 도달하는 지점. 대차합계 요약과 함께 최종 완결 버튼(`[통합 지급요청]`, `[최종 결재]`)이 위치한다.

## 3. 목적 지향 Z-패턴 설계를 위한 4대 본질 질문 (4 Teleological Core Questions)

모든 메뉴와 화면의 Z 구조를 설계할 때, 엔지니어와 기획자는 반드시 아래 **4대 본질 질문에 대한 명확한 개념 흐름**을 수립하고 이를 UI 레이아웃에 1:1로 투영해야 한다:

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│ [질문 2] "그 목표에 도달하기 위해 알아야 하는 정보는 무엇인가?"                   │
│  ➔ ① [좌상단 (Scope)]: 정산 연월, 대상 거래처, 지급 미완료(미정산) 대상 스코핑   │
│  ➔ ② [우상단 (Pipeline)]: 상대방 거래명세서 엑셀 유입, 데이터 파이프라인 트리거   │
├──────────────────────────────────────────────────────────────────────────────────┤
│                                                                                  │
│ [질문 3] "어떤 순서(Sequence)로 인지와 조작이 흘러가고 있는가?"                   │
│  ➔ ③ [중앙 본문 (Inspection)]:                                                   │
│     1단계: 🟢일치 / 🟡할증차액 / 🔴단독 청구 상태 조망                            │
│     2단계: 인라인 비고(현장대기, 2곳상차)로 차액 원인 파악                         │
│     3단계: 1클릭 원인 조치 (차액 승인, 배차 생성, 오청구 제외)                    │
│                                                                                  │
├──────────────────────────────────────────────────────────────────────────────────┤
│ [질문 4] "최종점에 도달하면 어떤 결과를 알게(확정하게) 되는가?"                  │
│  ➔ 대차대조 무결성 요약: 📄 엑셀 청구총액 = 🟢 지급 확정액 + 🚫 반려액 (차액 ₩0)  │
│                                                                                  │
│ [질문 1] "이 메뉴의 최종 목표(Terminal Objective)는 무엇인가?"                   │
│  ➔ ④ [우하단 (Terminal Action)]: 단일 [통합 매입 지급요청 생성] 발행 종결        │
└──────────────────────────────────────────────────────────────────────────────────┘
```

### 4대 본질 질문 정의
1. **질문 1: "이 메뉴의 최종 목표(Terminal Objective)는 무엇인가?"**
   - 화면의 우측 하단(④ Terminal Action)에 위치할 최종 완결 행위의 본질을 규정한다.
   - 예: *"이번 달 운송사 청구액과 당사 배차를 1원도 틀림없이 대사하여 단 1건의 [통합 매입 지급요청 번들]을 회계에 발행하는 것."*
2. **질문 2: "그 목표에 도달하기 위해서 알아야(세팅해야) 하는 정보는 무엇인가?"**
   - 화면의 좌측 상단(① Scope)과 우측 상단(② Pipeline)에 위치할 범주와 유입 데이터를 규정한다.
   - 예: *정산 대상 연월(2026-07), 정산 대상 운송사(경기), 지급 상태(지급 미완료 건만), 상대방 거래명세서 엑셀 원본.*
3. **질문 3: "어떤 순서(Cognitive Sequence)로 인지와 조작이 흘러가고 있는가?"**
   - 화면의 중앙 본문(③ Inspection)에서 사용자의 시선과 조작이 역류 없이 자연스럽게 대각선으로 흐르도록 배치한다.
   - 예: *상태 배지 확인 ➔ 1:1 대사 그리드에서 불일치 확인 ➔ 인라인 원클릭 승인/제외 조치 ➔ 차액 0원 수렴.*
4. **질문 4: "최종점에 도달하면 어떤 결과(Audit Result)를 알게(확정하게) 되는가?"**
   - 화면 최하단(④)에서 사용자가 안심하고 최종 버튼을 누를 수 있는 대차대조 검증 결과를 요약 표출한다.
   - 예: *[엑셀 청구 총액 ₩17,450,000 = 지급 확정 ₩17,450,000 (74건) + 반려 ₩0 | ⚖️ 대차 차액 ₩0]을 확정.*

## 4. 금지 패턴 (Anti-Patterns)

- 🚫 **목적 불분명 폼 (Aimless Form)**: 최종 목표와 결과가 무엇인지 모른 채 필드만 나열된 화면.
- 🚫 **중간 붕 뜸 버튼 (Floating Middle Button)**: 데이터 검증 영역 중간이나 상단에 최종 실행 버튼이 배치되어 검증 완료 전 성급한 클릭을 유도하거나 시선을 가로막는 형태.
- 🚫 **시선 역류 (Reverse-Flow)**: 하단에서 데이터를 검토한 뒤 다시 상단으로 올라가서 버튼을 찾는 형태.
- 🚫 **상단 4단 중첩 패널**: 필터, 통계, 검색, 버튼이 상단에 4줄 이상 중첩되어 메인 작업대가 쪼그라드는 형태.

---

## 5. 기대 효과 및 편익 (Benefits)
- **인지 부하 제로**: 4대 질문에 대한 답이 화면에 그대로 배치되어 교육 없이도 누구나 직관적으로 업무 완결.
- **감사 추적성 및 회계 무결성 100% 보장**: 최종 결과가 대차대조 ₩0으로 확정되므로 무누락/무오류 달성.
- **최소 조작 & 최대 편익**: 불필요한 번복 조작 없이 좌상단 ➔ 우하단 1-Way 단축 흐름 완결.
