## 1. 발상 배경 (Context & Problem)

### 1.1 현장 상황 및 문제의식
- **실시간 통화 관제와 VRAM 경합**: Space Consult Assist는 상담사 통화 중 WASAPI 루프백 및 `faster-whisper` 기반 실시간 STT를 구동한다.
- **범용 7B~8B LLM의 한계**:
  - 기존 설정(`exaone3.5` 등 7B~8B급 모델)은 4-bit 양자화 상태에서도 5~6GB 이상의 VRAM을 점유한다.
  - 상담사용 일반 업무 PC 또는 노트북(RTX 3060/4060, 6~8GB VRAM) 환경에서 Whisper STT와 LLM이 동시 가동되면 VRAM 부족(OOM)이 발생하거나 심각한 스와핑 지연(1.5~3초)이 발생한다.
  - 실시간 전화 상담 보조의 특성상 발화 종료 후 **1초 이내(골든타임)**에 상담 화면에 추천 스크립트와 부품코드가 표출되어야 한다.
- **단일 특수 목적의 명확성**:
  - 본 시스템에서 LLM에 요구되는 역할은 창작이나 범용 대화가 아니다.
  - "고객의 구어체 발화 텍스트 ➔ 18개 표준 부품코드 중 1개 매핑 + 핵심 증상 키워드 1개 ➔ 100% 문법 무결성 JSON 출력"이라는 **초고도로 정형화된 단일 정보 추출(Single-Task Information Extraction)**이다.

## 2. 핵심 아이디어 (Core Idea)

### 2.1 Sub-1B ~ 1.5B 초경량 모델(SLM)의 도메인 특화 QLoRA 파인튜닝
- **베이스 모델**: `Qwen2.5-0.5B-Instruct` (약 4.9억 파라미터) 또는 `Qwen2.5-1.5B-Instruct`.
- **극단적 경량화**:
  - 4-bit 양자화(GGUF Q4_K_M) 시 모델 파일 크기 **~380MB** (0.5B) / **~1.1GB** (1.5B).
  - VRAM 점유량 **500MB~1.2GB** 수준으로, Whisper STT와 GPU를 완벽하게 공유(합산 VRAM < 3GB).
  - 로컬 CPU 전용(CPU-only)으로 구동해도 100~150ms 이내 응답 가능.
- **초고속 추론 지연시간(Latency)**:
  - 응답 토큰이 20~30 토큰에 불과하므로, 초당 120~180 토큰 생성 속도로 **50~150ms 만에 응답 완결**.
  - 체감상 지연 없는 실시간 관제 UI 구현 가능.
- **100% 무결성 제약 디코딩(Constrained Decoding)**:
  - Ollama `format: "json"` 및 Pydantic 스키마 결합을 통해 환각 및 JSON 파싱 에러율 0% 보장.

### 2.2 현장 정비(모바일)를 위한 VLM(경량 시각-언어 모델) 확장
- 모바일 현장정비사 및 출장 접수 시 첨부되는 장비 명판(Serial Number, 모델명) 및 계기판 에러코드 표시창을 `Qwen2.5-VL-3B` 또는 `Moondream2`(1.8B)로 로컬 자동 OCR/인식하여 정비 일지에 원클릭 자동 입력.

## 3. 기대 효익 (Expected Benefits)

1. **하드웨어 제약 돌파 (최소 비용)**: 고가의 GPU 서버 증설 없이 기존 상담사 PC의 6~8GB 랩탑 GPU 또는 CPU만으로 100% 로컬 독립 가동.
2. **응답 속도 혁신 (10배 향상)**: 1,500~2,500ms 소요되던 Fallback 추론 지연시간을 100~200ms 수준으로 단축하여 실시간 전화 응대 최적화.
3. **도메인 정밀도 극대화**: 청소장비 부품 18종 및 특수 고장 증상에 1:1 맞춤 학습되어 범용 LLM 대비 오분류율 급감.
4. **완벽한 데이터 보안**: 고객 통화 내용과 설비 정보가 외부 API로 유출되지 않는 100% 폐쇄망/온디바이스 보안 체계 달성.
