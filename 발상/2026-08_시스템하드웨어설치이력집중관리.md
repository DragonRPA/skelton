## 핵심 발상

프로젝트 레벨과 시스템 레벨의 의존성은 **관리 계층이 달라야 한다.**

```
[프로젝트 레벨]   Python 패키지, npm 패키지, 가상환경  → 프로젝트 폴더 내 관리
[시스템 레벨]     CUDA, cuDNN, GPU 드라이버, .NET,
                  Visual C++ Redistributable 등        → 단일 집중 관리
```

현재 문제:
- AI 에이전트가 프로젝트마다 "CUDA 설치하세요" 안내
- 사장님이 매번 이미 설치했는지 기억해야 함
- 중복 설치 시 버전 충돌 위험
- 어느 버전이 설치되어 있는지 아무도 모름

---

## 필요한 것: 시스템 설치 이력 대장

**개념**: 한 대의 PC에 설치된 모든 시스템 레벨 소프트웨어를
단 하나의 문서로 집중 관리한다.

### 관리 대상 분류

| 분류 | 항목 예시 |
|------|-----------|
| GPU / CUDA | CUDA Toolkit 버전, cuDNN 버전, GPU 드라이버 버전 |
| Python 런타임 | Python 3.x 버전, 설치 위치 |
| Node.js / npm | 버전, 설치 위치 |
| .NET / VC++ | 버전별 설치 여부 |
| Docker | 버전, WSL2 연동 여부 |
| 기타 시스템 툴 | ffmpeg, git, cmake 등 글로벌 설치 항목 |

### 관리 방식 (안)

```
D:\01.AntiGravity\
└── system_registry\
    └── system_install_log.md   ← 설치 이력 단일 파일
```

또는 skelton 내에 별도 섹션으로 관리.

## 이 발상이 해결하는 문제

1. **중복 설치 방지**: AI 에이전트가 설치 전 이 문서를 확인하면 "이미 설치됨" 판단 가능
2. **버전 충돌 방지**: 여러 프로젝트가 같은 CUDA를 쓰는지 확인 가능
3. **AI 에이전트 행동 통제**: "설치 지시 전 system_install_log.md 먼저 확인" 규칙 추가 가능
4. **PC 이전/재설치 시 복원 기준**: 어떤 것들을 다시 깔아야 하는지 즉시 파악
