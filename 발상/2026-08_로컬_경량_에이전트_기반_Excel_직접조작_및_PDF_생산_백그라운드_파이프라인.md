## 1. 발상 배경 및 문제의식 (Context)

1. **브라우저 샌드박스의 한계**:
   - 웹 브라우저 프론트엔드는 보안 샌드박스 제약으로 인해 로컬 파일시스템에 직접 접근하거나, Microsoft Excel 정품 COM 엔진을 직접 구동하여 셀 단위로 정밀 제어한 뒤 네이티브 PDF로 출력하는 작업에 구조적 한계가 존재함.
   - 브라우저 내 텍스트 오버레이 방식은 템플릿의 셀 위치, 글꼴, 마스킹 좌표를 일일이 보정해야 하는 유지보수 부담이 발생함.
2. **검증된 성공 경험 (Proven Architecture)**:
   - 최근 프로젝트에서 로컬에 상주하는 초경량 에이전트(Local Sidecar Agent)를 구동하고, 브라우저와 로컬 통신(Localhost HTTP/WebSocket)을 통해 고난도 백그라운드 작업을 에이전트가 완벽하게 대행 처리하는 아키텍처를 성공적으로 구현함.

## 2. 핵심 발상 및 아키텍처 (Core Concept)

### 2.1 초경량 로컬 에이전트 배포 및 프론트엔드 모니터링
- **원클릭 다운로드 & 간편 설치**:
  - 프론트엔드 시스템 내에서 직원이 언제든지 로컬 에이전트 설치 파일(`.exe` / 경량 실행기)을 다운로드받을 수 있도록 지원.
  - 에이전트가 미실행 상태일 경우, 화면에 부드러운 알림과 함께 원클릭 다운로드/실행 가이드 표출.
- **실시간 헬스체크 모니터링 (Health-Check)**:
  - 프론트엔드 UI 상단 헤더 또는 설정 화면에 에이전트 연결 상태(`🟢 에이전트 작동중` / `🔴 미연결`)를 실시간 감지하여 노출.

### 2.2 엑셀 원본 파일 직접 조작 및 네이티브 PDF 생산
- **실제 엑셀 서식(`.xlsx`) 직접 셀 주입**:
  - 로컬 에이전트가 회사의 공식 원본 엑셀 양식 파일(`.xlsx`)을 직접 로드하여 정확한 셀 좌표(`B5`, `C12` 등)에 실시간 계약/장비 데이터를 주입.
- **정품 PDF 엔진 무손실 출력**:
  - 엑셀 자체 엔진 또는 경량 변환기를 통해 마이크로소프트 엑셀 정품 퀄리티 그대로 100% 무손실 벡터 PDF를 백그라운드에서 즉각 생산.

### 2.3 백그라운드 생산 & 브라우저 병합 파이프라인 연동
- **비동기 고속 생산**:
  - 프론트엔드에서 계약 팩 발행 요청 시 ➔ 로컬 에이전트가 백그라운드에서 1~3대 서류(계약서, 체크리스트, 안전점검표)를 수초 내 생산하여 바이너리 반환 ➔ 브라우저가 이를 받아 구글 드라이브 외부 서류들과 최종 결합.
- **로컬 지정 보관소 자동 누적 아카이빙 (Local Auto-Archiving)**:
  - 생산된 모든 계약 문서 및 점검표 원본을 회사의 지정된 로컬 드라이브 경로(예: `D:\기연리프트_전자문서보관소\YYYY-MM\고객사_현장\`)에 체계적으로 자동 누적 저장하여 영구적인 로컬 감사 백업 구축.

## 3. 기대 효익 (Expected Benefits)

1. **품질 완벽성 (100% Zero-Defect)**:
   - 마이크로소프트 엑셀에서 사용자가 작성한 서식과 디자인, 폰트, 열 너비, 줄바꿈이 0.1mm 오차도 없이 100% 동일하게 PDF로 출력됨.
2. **업무 효율성 & 완전 자동화 (Zero-Effort)**:
   - 직원은 웹 화면에서 버튼 한 번만 누르면, 로컬 엑셀 수정부터 PDF 변환, 드라이브 원본 병합, 로컬 폴더 자동 저장까지 모든 과정이 백그라운드에서 완결됨.
3. **견고한 로컬 아카이빙**:
   - 클라우드뿐만 아니라 로컬 PC/사내 서버에도 날짜별, 고객사별로 원본 서류가 완벽히 정리되어 보존됨.
