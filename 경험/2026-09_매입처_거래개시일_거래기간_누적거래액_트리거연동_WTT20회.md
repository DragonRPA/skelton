# 매입처 관리 3대 핵심 거래지표(거래개시일·거래기간·누적거래액) 설계 및 자산취득/매입정산 2대 트리거 자동 연동 (WTT 20회 관통 스트레스 테스트 완료)

- **작성일시**: 2026-09-05 18:27
- **해당 버전**: v1.6.0.Build.192
- **도메인**: 자산/구매/회계/매입처 (Vendors, Assets, Purchase Settlements)
- **핵심 목표**: 실무자의 수동 계산 및 번복 입력을 원천 차단하고, 자산취득 및 매입정산 확정 시 매입처 거래개시일·거래기간·누적거래액을 1원의 누락 없이 자동 연동·영구 보존

---

## 1. 배경 및 문제 정의
- 고소작업대 렌탈 도메인에서 장비 공급사, 운송 협력사, 소모품/부품 구매처, 외주정비처 등 수십 개 매입처와의 거래가 지속 발생함.
- 기존에는 매입처 마스터 테이블에 기본 연락처 정보만 저장되어 있어, "해당 매입처와 언제부터 거래했는지", "현재까지 총 얼마의 매입 거래가 발생했는지", "거래 기간이 얼마나 경과했는지"를 파악하기 위해 별도의 엑셀 대장이나 정산서를 수동 집계해야 하는 실무적 비효율이 존재함.
- 사장님의 명확한 지시:
  > **"매입처 관리의 거래개시일과 거래기간, 누적거래액이 관리되면 좋겠어. 누적거래액은 매입거래 누계액이야. 자산취득 또는 매입정산 할 때, 트리거 하면 될것같아"**

---

## 2. 도메인 및 데이터 모델 설계 (SSOT & Schema)

### 2.1 매입처 마스터 (`Vendor`) 확장
- `firstTradeDate?: string`: 최초 거래개시일 (`YYYY-MM-DD`). 수기 입력 가능하며, 첫 자산취득 또는 매입정산 시 자동으로 최소 일자로 기록·소급.
- `lastTradeDate?: string`: 최근 거래일 (`YYYY-MM-DD`). 신규 거래 인입 시 가장 최신 일자로 전이.
- `totalPurchaseAmount?: number`: 매입거래 누적거래액 (원). 0원 기본값, 취득/정산 시 정밀 가산.
- `calculateTradeDuration(firstTradeDate)`: 거래개시일로부터 현재까지의 경과 기간을 "X년 Y개월 (Z일)" 형식으로 동적 산출.

### 2.2 DDL 스키마 패치 (`schema.sql`)
```sql
ALTER TABLE vendors ADD COLUMN IF NOT EXISTS firstTradeDate VARCHAR(10);
ALTER TABLE vendors ADD COLUMN IF NOT EXISTS lastTradeDate VARCHAR(10);
ALTER TABLE vendors ADD COLUMN IF NOT EXISTS totalPurchaseAmount BIGINT DEFAULT 0;
```

## 3. 2대 트리거 자동 연동 및 일괄 동기화 엔진

### 3.1 트리거 A: 당사자산 취득 시 (`acquireAsset`, `batchAcquireAssets`)
- 신규 자산 등록 및 엑셀 일괄 등록 완료 즉시 `triggerVendorPurchaseMetric` 호출.
- 매핑 기준: `asset.vendorId` 또는 `asset.supplier` 상호명 매핑.
- 취득가액(`acquisitionPrice`)을 누적거래액에 1원 단위로 정확히 가산하고, `acquisitionDate`를 대조하여 `firstTradeDate` 소급 및 `lastTradeDate` 갱신.

### 3.2 트리거 B: 매입정산 확정 시 (`confirmPurchaseSettlement`)
- 운송비, 소모품 구매, 장비 임차료, 외주정비비 등 월말 매입정산 확정 승인 즉시 `triggerVendorPurchaseMetric` 호출.
- 매핑 기준: `settlement.vendorId` 또는 `settlement.vendorName` 상호명 매핑.
- 정산총액(`totalAmount`)을 누적거래액에 가산하고, 지급일(`paymentDate` 또는 `settlementYm-01`)로 거래일자 반영.

### 3.3 전사 일괄 재집계 헬퍼 (`recalculateAllVendorMetrics`)
- 기존 레거시 데이터와의 정합성을 보장하기 위해, 전사 당사자산(`ownerType === 'OWNED'`)과 매입정산 대장을 전수 스캔하여 1원도 오차 없이 일괄 동기화하는 감사 헬퍼 탑재.
- `await db.awaitPendingWrites()`를 동기 대기하여 헌장 5.2(무음 실패 방지) 준수.

## 6. 결론 및 향후 자산 관리 표준화 시사점
- 자산취득과 매입정산이라는 렌탈 도메인의 2대 핵심 지출 파이프라인이 매입처 마스터와 실시간 동기화됨으로써, 영업/구매/회계 부서 간의 정보 단절이 완전히 해소됨.
- 실무자는 별도의 계산 작업 없이도 매입처 목록 조회만으로 파트너십 기간과 전사 거래 기여도를 즉시 파악할 수 있어 전사 사명인 **'최대 편익 달성'**을 실현함.
