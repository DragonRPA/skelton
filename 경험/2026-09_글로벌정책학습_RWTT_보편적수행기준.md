## 1. 학습 배경
WTT(도메인 관통 스트레스 테스트)의 '개념'은 정립되었으나, 실제 개발 과정에서 이를 '어떻게 실행할 것인가'에 대한 구체적 행동 강령이 부재했다. 이에 따라 e-Bro 등 특정 프로젝트에 국한되지 않고, 모든 프로젝트에 적용 가능한 **RWTT(Real-world Work-Through Test)의 보편적 4대 수행 기준**을 수립하여 글로벌 정책(AGENTS.md) 5.8 항목으로 편입했다.

## 2. RWTT의 본질
**"무엇을 테스트할 것인가(WTT)를, 한 치의 날조 없이 어떻게 철저히 실증할 것인가(RWTT)"**
모의(Mock) 객체나 가짜 성공 신호를 전면 배제하고, 실제 물리적 환경에서 사용자의 실제 동선을 따라 종단간 결과물을 100% 창출해 내는 것이다.

## 3. 학습된 보편적 4대 수행 기준 (AGENTS.md 5.8 반영)

1. **조작 동선의 UI/API 실증 (No-Mocking Rule)**: DB 강제 주입(Raw Query)을 금지하며, 반드시 실제 UI 클릭이나 상용 API 호출을 통해서만 테스트한다.
2. **외부 의존성 물리적 작동 필수 (Physical Dependency Trigger)**: "성공으로 친다"는 가정을 불허한다. 실제 파일(PDF, Video)이 써지고 메일 포트가 열려야만 PASS로 인정한다.
3. **비정상 유저 페르소나 빙의 (Adversarial Persona Play)**: 정상 흐름만 쫓지 않고, "게으르고 멍청하고 부도덕한 사용자"의 시각에서 의도적인 마찰(Friction, 에러 조작 등)을 반드시 1회 이상 주입한다.
4. **실물 데이터 기반 사후 감사 (Post-mortem Physical Audit)**: 에이전트의 구두 보고는 무시하며, 오직 실제 DB 스냅샷, 물리 파일 속성, 타임라인 인과율만을 증거로 채택하여 교차 검증한다.
