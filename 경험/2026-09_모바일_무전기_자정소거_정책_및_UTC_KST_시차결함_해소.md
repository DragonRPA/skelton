## 2. 무전기 대화 음성 소거 정책의 본질
1. **당일 전용 휘발성 PTT 원칙**:
   - 무전기는 대화 기록을 수개월 보관하는 메신저가 아니라, 현장 작업자와 기사 간의 **실시간 1회성 PTT(Push-To-Talk) 소통망**이다.
   - 음성 Base64 데이터는 텍스트 대비 용량이 수천 배 크므로, 누적될 경우 스마트폰 웹 브라우저의 `localStorage`(5MB 한도)를 초과하여 앱 전체가 멈추거나 백화(Crash)된다.
   - 따라서 매일 자정(00:00 KST)에 전일 대화 기록을 깨끗이 비워 5MB 용량을 원상 복원한다.
2. **중앙 서버(DB) 무부하 설계**:
   - 사원 간의 모든 일상 음성 패킷을 중앙 DB에 영구 적재하지 않고, Supabase Realtime의 가벼운 웹소켓 브로드캐스트로 0초 전파한 뒤 단말기에 당일분만 임시 보관한다.
3. **20건 초과 시 자동 압축**:
   - 당일 대화가 20건을 초과하면 최신 20건만 고음질 음성을 유지하고, 그 이전 대화는 Base64 오디오를 제거하고 텍스트 자막만 남겨 브라우저 성능을 보호한다.

## 3. 자정 즈음 무전기 불통의 근본 원인 분석 (UTC vs KST 시차 버그)
- **증상**: 자정(00:00 KST) 즈음부터 말을 해도 대화 피드에 말풍선이 전혀 뜨지 않고, 음성 송수신이 불통되는 현상 발생.
- **근본 원인**:
  1. 음성 메시지가 생성될 때 생성일자는 `new Date().toISOString()` (예: `2026-09-05T15:05:00.000Z`)로 기록된다. 이는 **영국 그리니치 천문대 기준의 UTC 시간**이다.
  2. 반면 소거 가드인 `getTodayDateStr()`은 기기의 **한국 로컬 시간(KST, UTC+9)**을 읽어 `2026-09-06`을 반환한다.
  3. 한국 시간 자정(00:00 KST)부터 아침 09:00 KST까지는 UTC 기준으로 아직 어제(`2026-09-05 15:00 ~ 23:59`)에 해당한다.
  4. 시스템이 `msg.createdAt?.slice(0, 10) === today`로 단순 문자열 비교를 수행했기 때문에, `"2026-09-05" === "2026-09-06"`이 `false`가 되어 **자정부터 아침 9시까지 9시간 동안 보낸 모든 음성이 "어제 지난 오래된 메시지"로 판정되어 `addHistory()`에서 무음 탈락(Discard)**되었다.
  5. 또한 1분 주기로 실행되는 `purgeOldHistoryIfNeeded()`가 자정 00시 00분에 즉시 과거 메시지를 소거하므로, 화면에는 이전 대화도 사라지고 새 대화도 추가되지 않아 무전기가 완전히 죽은 것처럼 보였던 것이다.

## 4. 해결 조치
- `getLocalDateStr(dateStr)` 헬퍼 함수를 신설:
  ```ts
  getLocalDateStr(dateStr?: string): string {
    if (!dateStr) return '';
    try {
      const d = new Date(dateStr);
      if (isNaN(d.getTime())) return '';
      return `${d.getFullYear()}-${String(d.getMonth()+1).padStart(2,'0')}-${String(d.getDate()).padStart(2,'0')}`;
    } catch {
      return '';
    }
  }
  ```
- `constructor`, `purgeOldHistoryIfNeeded()`, `addHistory()` 4개 위치의 `slice(0, 10)`을 전면 퇴출하고 `this.getLocalDateStr(m.createdAt) === today`로 교체.
- UTC ISO 문자열을 브라우저의 한국 로컬 타임존으로 파싱하여 비교함으로써, 자정 00시 00분 01초부터 생성되는 모든 메시지가 정확히 오늘(KST)로 판정되어 지연 없이 0초 표시 및 재생되도록 완벽 해결.

## 5. 재발 방지 원칙
- 모든 시간 비교 및 필터링 시, `toISOString().slice(0, 10)`과 같은 **UTC 원시 문자열 슬라이싱 비교를 전면 금지**한다.
- 날짜 경계선 로직은 반드시 `new Date(isoStr)`를 통해 로컬 타임존(KST)으로 역파싱된 연/월/일로 비교해야 자정 및 야간/새벽 시간대의 데이터 누수를 원천 차단할 수 있다.
