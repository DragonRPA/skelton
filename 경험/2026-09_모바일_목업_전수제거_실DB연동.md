# 모바일 전용 메뉴 목업 전수 제거 및 실DB 1:1 연동 경험 (Build.156)

- **일시**: 2026-09-05 11:30
- **맥락**: 모바일 5개 부서 WTT 감사 이후 사용자 명시적 지시: "핸드폰 전용 메뉴에서 임시로 삽입한 데이터, 하드코딩되어 표시되고 있는 정보들 전부 삭제. 실제 DB 에서 올라오는 내용만 표시. 모든 메뉴 전수검사"
- **핵심 문제**:
  - `MobileExecutiveHome.tsx`에 남아있던 서희건설 4대 단가할인 특약, 고압세척기 385만원 지출결의 등 정적 목업과 가짜 토스트 버튼.
  - `MobileAdminHome.tsx`의 청구월 fallback 하드코딩 (`'2026-08'`).
  - `MobileDispatchList.tsx`의 기사 배정 모달 내 '테스트 예시 1' (`경기88바1234 이기사...`) 더미 버튼.
- **해결 및 적용**:
  1. 모바일 소스코드 24개 파일 전수 스캔 스크립트 작성 및 자동 진단 수행.
  2. `MobileExecutiveHome.tsx` 결재 대기 큐를 실제 DB 3대 테이블(`consumablePurchases`, `purchaseSettlements`, `payrollClosings`)과 1:1 실시간 바인딩.
  3. [승인] 클릭 시 실제 DB update 및 `await db.awaitPendingWrites()` 동기 트랜잭션 보장 (헌장 5.2).
  4. 대기 건 부재 시 "현재 경영진 최종 결재 대기 건이 없습니다." 정직한 빈 상태 표출.
  5. 관리홈 청구월 및 배차 대장 더미 버튼 등 발견된 모든 하드코딩 잔재 영구 제거.
  6. `npm run build` 0 Type Error 검증 완료.
- **교훈 및 원칙**:
  - 시스템의 신뢰성은 "화면에 보이는 데이터가 진짜 DB의 기록인가"에서 시작된다.
  - 임시 목업이나 테스트용 더미 버튼은 개발 편의를 위해 삽입되더라도 릴리즈 전에 전수 검사로 완전 제거되어야 하며, 데이터가 없을 때는 가짜 예시가 아닌 정직한 Empty State를 제공해야 사용자 신뢰가 유지된다.
