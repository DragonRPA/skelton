# 연차 및 초과근무(OT) 기능 WTT 20회 관통 검증 및 도메인 정밀 개편

---

## 📌 1. 개요 및 배경
- **일시**: 2026-09-05
- **대상 도메인**: 근태/HR 관리 (연차 쿼터 부여, 연차/반차 소진, 초과근무 OT 등록, 급여 대장 통산 연동)
- **추진 배경**:
  - 기존 연차 관리 시스템에서 다일 연차(5일 연속 등)를 신청해도 무조건 `usedDays = 1.0`으로 고정 처리되는 중대 결함 적발.
  - 잔여 연차 초과 신청 차단 가드 부재, 기간 중복 신청 방어 미비, 날짜 역전(`endDate < startDate`) 미방어 결함 적발.
  - 브라우저 원시 `alert` 5건 잔존으로 인한 헌장 5.2 위반 해소.
  - 헌장 5.5(도메인 관통 스트레스 테스트 WTT 원칙)에 따른 5대 축 20회 스트레스 시나리오 설계 및 전수 100% 관통 검증 수행.

## 🔍 2. 적발된 결함 및 정밀 개편 내역

### 2.1 다일 연차 일수 계산 오류 원천 개편
- **결함**: `leaveType === 'ANNUAL'`일 때 `usedDays = 1.0` 고정 코드로 인해 5일 휴가를 가도 1일만 차감되는 오류.
- **조치**: `Math.abs(endD.getTime() - startD.getTime()) / (1000 * 60 * 60 * 24) + 1` 일수 계산식 적용으로 실제 기간 일수 정밀 차감.

### 2.2 4대 유효성 방어 가드 구축
1. **잔여 연차 초과 차단 가드**: `usedDays > summary.remainingDays` 차단.
2. **날짜 역전 차단 가드**: `endDate < startDate` 차단.
3. **기간 중복 연차 신청 차단 가드**: 동일 임직원의 기존 승인 연차 기간과 오버랩(`hasOverlap`) 시 신청 원천 차단.
4. **OT 시간 유효성 가드**: `0시간 이하`, `24시간 초과`, `공백 사유` 입력 원천 차단 및 급여 마감월(`APPROVED`) 소급 등록 방어.

### 2.3 비동기 쓰기 대기 및 브라우저 alert 전면 퇴출 (헌장 5.2)
- `updateAnnualLeaveQuota`, `addLeaveUsage`, `deleteLeaveUsage`, `addOvertimeRecord`, `deleteOvertimeRecord`에 `await db.awaitPendingWrites()` 추가하여 무음 실패 방지.
- 브라우저 `alert` 5건 전면 퇴출 ➔ `showErrorModal` 및 자체 `showToast` 컴포넌트로 전환.

### 2.4 Gutenberg Z-패턴 4단계 전사 연차 대차대조식 바 탑재 (헌장 3.5)
- 연차 탭: $\text{총부여 } N\text{일} = \text{총소진 } N\text{일} + \text{총잔여 } N\text{일} \mid \text{대차 차액 } 0.0\text{일}$ 항등식 바 고정 탑재.
- OT 탭: 당월 전사 초과근무 건수 및 총 누적시간 통산 바 탑재.

## 💡 4. 배운 점 및 교훈 (Experience)
1. **단순 UI 입력 폼이라도 도메인 라이프사이클과 연결되어야 한다**:
   단순한 연차 폼에서도 1일 고정 버그, 음수 잔여 발생 버그, 중복 신청 버그 등이 숨어있었으며, WTT 5대 축 스트레스 테스트를 통해 사전에 100% 적발 및 퇴출할 수 있었다.
2. **Gutenberg Z-패턴 대차대조식의 강력함**:
   하단 대차대조식 검증 바를 통해 관리자가 전사 직원의 연차 부여/소진/잔여 합계의 일치 여부를 1초 만에 확인하고 데이터 무결성을 신뢰할 수 있게 되었다.
