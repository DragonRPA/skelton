## 실제로 일어난 것

### 성취한 것
- 6,800개 음성 파일 → 32,693건 구조화 데이터 완성
- 멀티 LLM 앙상블(Gemma 12b / 4b / Gemini)로 엔진별 비교 분석 구조 확보
- 16스레드 병렬 병합으로 32,693건을 38초 만에 처리
- 브라우저 단일 HTML 대시보드 생성 (Chart.js 로컬 번들, CDN 의존 없음)

### 예상보다 어려웠던 것
- **파일명 정형화**: 슬라이딩 타임스탬프 매처를 직접 설계해야 했음. 정규식 만으로는 8가지 형식을 모두 처리할 수 없었음
- **LLM JSON 불안정성**: 배치 30건 중 1건 파싱 실패 시 30건 전체 강등. 부분 파싱 + 재시도 로직을 나중에 추가해야 했음
- **통계 왜곡**: 미분류 건이 "흡입계통"으로 수개월간 집계됨. 잘못된 default 하나가 전체 통계의 신뢰도를 오염시킴

### 예상보다 빠르게 해결된 것
- GPU 가속 STT: RTX 5080 CUDA 연동이 예상 대비 빠르게 안정화됨
- 앙상블 병합: 16스레드 구조가 처음부터 잘 작동함

## 이 경험에서 체득한 원칙

1. **"이름과 실제 동작이 일치해야 한다"**
   — "AI 군집화"라 불렀지만 실제로는 정규식이 95%를 처리하고 있었음. top_k=200의 착시.

2. **"분류 실패는 중립으로 격리해야 한다"**
   — default를 특정 카테고리로 설정하는 것은 통계에 거짓말을 심는 것.

3. **"편의상 복사된 코드는 반드시 나중에 부채가 된다"**
   — SSOT 위반이 두 파일 간 규칙 불일치로 이어짐.

4. **"부분 실패는 부분만 격리해야 한다"**
   — 배치 1건 실패가 30건 전체를 강등시키는 구조는 설계 결함.
