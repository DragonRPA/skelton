# 법인차량 등록 후 웹앱 주유/운행 등록 차량 선택 동기화 및 WTT 10회 완결

## 1. 개요
- **일시**: 2026-09-09 14:10 KST
- **버전**: `v1.11.4.Build.16`
- **배경**: PC 법인차량운행일지(`VehicleOperationLogPage.tsx`)에서 등록된 법인 차량(`corporateVehicles`)이 모바일 웹앱(`MobileVehicleLog.tsx`) 주유 영수증 및 운행일지 등록 시 비동기 로딩 타이밍 결함 및 HTML select 상태 불일치로 인해 선택이 영구 차단되던 결함을 100% 척결하고, WTT 10회를 통해 무결성을 확정함.

## 2. 결함 분석 (Root Causes)
1. **비동기 로딩 타이밍 결함**: 마운트 초기 `corporateVehicles`가 빈 배열(`[]`)일 때 `defaultVehicleId`가 `''`가 되고, 이후 데이터가 도착해도 `useState` 초기값이 갱신되지 않아 `fuelVehicleId`와 `opVehicleId`가 빈 문자열에 영구 고착됨.
2. **HTML `<select>`와 React State 간의 괴리**: 드롭다운에 `<option value="">`가 없어 화면상으로는 첫 번째 차량이 선택된 것처럼 보이나 실제 React 상태값은 `''`임. 사용자가 [저장]을 누르면 `showErrorModal('차량을 선택해 주십시오.')` 팝업이 뜨고, 첫 번째 옵션을 다시 탭해도 `onChange` 이벤트가 발생하지 않아 선택이 불가능해짐.
3. **모바일 진입 시 데이터 동기화 누락**: PC 웹과 달리 모바일 탭 진입 시 `loadTablesForMenu('vehicle_log')`를 호출하지 않아 다른 기기나 PC에서 신규 등록된 차량이 모바일 캐시에 즉시 반영되지 않음.
4. **정렬 및 상태 식별 부재**: 본인 전담 차량(`primaryDriverId === currentUser.id`)이 상단에 고정되지 않고, 비활성 휴차(`isActive: false`)가 가용 차량과 섞여 혼란 유발.

## 3. 해결 방안 (Architecture Solution)
1. **모바일 마운트 시 자동 데이터 동기화**:
   - `useEffect`로 `loadTablesForMenu('vehicle_log')`를 호출하여 최신 DB 데이터를 보장.
2. **스마트 정렬 및 가용 차량 우선 채번**:
   - `sortedCorporateVehicles`: 본인 배정 차량 최우선(`★내 배정차량`), 가용 차량 우선, 차량번호 오름차순, 휴차 후순위(`[휴차]`).
   - `defaultVehicleId`: 가용 1순위 차량 안전 반환.
3. **수동 선택 의도 추적 및 자동 동기화 (`useEffect`)**:
   - `hasManuallySelectedFuel`, `hasManuallySelectedOp` 플래그 도입.
   - 비동기 로딩 지연 또는 신규 차량 등록 시 수동 미선택 상태를 감지하여 본인 전담 차량으로 100% 자동 동기화.
   - 운행자가 명시적으로 수동 선택한 차량은 백그라운드 리프레시 시에도 보존.
4. **드롭다운 플레이스홀더 및 `[목록 갱신]` 원터치 버튼 탑재 (헌장 3.1 & 3.2)**:
   - 빈 목록 및 미선택 플레이스홀더 추가.
   - 헤더 레이블 우측에 `RotateCw` 아이콘의 `[목록 갱신]` 원터치 버튼 제공.
5. **엄격한 유효성 검증 가드 (헌장 5.2)**:
   - 저장 시 `!vehicleId || !sortedCorporateVehicles.some(v => v.id === vehicleId)` 체크로 고아/유령 차량 등록 차단.

## 4. WTT 10회 관통 스트레스 테스트 결과
- 5대 축(공간·물리·시간·비용·수량) 매트릭스 10회 전수 통과 (10/10 PASS).
- 3대 보존 법칙(차량 매핑 보존, 누적 주행거리 단조 증가 보존, 연비/회계 대차대조 보존) 100% 입증.

## 5. 배운 점 및 재발 방지 원칙
- React 비동기 데이터 폼 컴포넌트 설계 시 초기 `useState(memoizedDefault)`에만 의존해서는 안 되며, 데이터가 비동기 도착하거나 런타임에 갱신될 때 상태를 자동 정렬·동기화하는 방어 `useEffect`와 사용자의 수동 조작 의도(`hasManuallySelected`) 추적 플래그를 반드시 페어로 설계해야 한다.
