# 매뉴얼 캡처 스튜디오 프로젝트 분리 보존(.mcs.json) 및 재편집 엔진 구축

- **일시**: 2026-09-10
- **범주**: 경험 (EXPERIENCE)
- **도메인**: 수동 매뉴얼 제작 전용 초고속 스튜디오 (`999.매뉴얼제작`)

---

## 1. 배경 및 당면 과제
- 기존 매뉴얼 제작 스튜디오는 캡처 이미지 위에 스탬프, 화살표, 말풍선 등을 배치한 후 `F10`을 누르면 파워포인트 전송용 단일 비트맵(`Step_NNN.png`)으로 합쳐져(Bake) 저장됨.
- 이로 인해 사후 매뉴얼 수정(오타 변경, 화살표 위치 5px 조정, 순서 변경 등) 시 캡처부터 모든 주석 작업을 처음부터 다시 해야 하는 생산성 손실 발생.
- "PPT로 보낼 때는 규격화된 일체형 이미지로 보내더라도, 스튜디오에서는 개별 객체 레이어가 살아있는 프로젝트 파일로 보존할 수 없는가?"라는 질문에서 착수함.

---

## 2. 핵심 아키텍처 및 해결 방법

### ① 9대 주석 객체 양방향 직렬화 인터페이스 (`to_dict` / `from_dict`)
- `StampItem`, `TextLabelItem`, `HighlightBoxItem`, `ArrowItem`, `StepArrowItem`, `ElbowArrowItem`, `CalloutItem`, `BlurMosaicItem`, `HotkeyBadgeItem` 전체에 직렬화 메서드를 구현하고 전역 `item_from_dict(data)` 팩토리 구축.

### ② 2중 무손실 원본 보존 전략 (Companion Image + Base64 Fallback)
- 프로젝트 파일(`.mcs.json`) 저장 시 같은 폴더에 순수 비트맵 원본(`Step_NNN_raw.png`)을 companion 파일로 저장하여 윈도우 탐색기에서 즉시 확인 가능하도록 함.
- 동시에 파일 이동이나 단독 배포 시 캡처 이미지가 유실되는 것을 원천 차단하기 위해 JSON 내부에도 base64 인코딩 이미지를 백업 수납함. (로컬 파일 우선 탐색 ➔ 없으면 base64 fallback 복원)

### ③ F10 무조작 100% 자동 3종 동시 저장 (Zero-Effort Automation)
- 사용자가 별도로 '저장' 버튼을 누르지 않아도, `F10` 슬라이드 생성 시 `captures_YYYYMMDD/` 폴더에 아래 3종 세트를 1회 클릭으로 동시 저장:
  1. `Step_NNN.png`: PPT용 고화질 일체형 이미지 (Bake)
  2. `Step_NNN_raw.png`: 주석 없는 순수 캡처 원본
  3. `Step_NNN.mcs.json`: 개별 객체 레이어가 모두 살아있는 프로젝트 파일

### ④ 스마트 번호 자동 재정렬 (Auto Re-indexing)
- 객체 삭제(마우스 우클릭 또는 `Delete` / `Backspace` 키) 시 중간 번호가 빠지면 뒤의 스탬프들이 자동으로 번호를 승계(`reindex_stamps()`)하여 번호가 꼬이지 않음.
- `Ctrl+Z` (Undo) 시 원래의 번호와 위치로 완벽 롤백.

### ⑤ 리본 메뉴 UI 연동
- 리본 메뉴 탭 1 `도구`에 `[프로젝트]` 그룹을 독립 배치하고 `📂 프로젝트 열기 (Ctrl+O)`, `💾 프로젝트 저장 (Ctrl+S)`, `🖼 이미지 열기`, `📋 클립보드 복사` 제공.
