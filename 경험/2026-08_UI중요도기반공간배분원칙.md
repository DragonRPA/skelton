## 실제로 일어난 것

### 채움-축소 균형 구현 결과

| 변경 | 구현 내용 | Score |
|------|----------|-------|
| 축소 | 1단계 풀폭 버튼 → 소형 보조 버튼 (160px) | 2 |
| 채움 | 분석 준비 상태 패널 신설 (군집화 사전 + 분석 스냅샷) | 8 |
| 데이터 | analysis_meta.json — 두 파이프라인 단계가 공유하는 단일 메타 파일 | — |

### 핵심 구현 결정

**단일 메타 파일 설계** (`analysis_meta.json`):
- 군집화 단계 → 사전 상태 기록
- 집계 단계 → 분석 결과 기록
- 두 단계가 동일 파일을 순차적으로 갱신 → 항상 최신 상태 유지

**커버율 기반 3단계 권고 로직**:
- 커버율 < 30%: 빨간 "군집화 재실행 권장"
- 커버율 30~60%: 주황 "집계 재실행 가능"
- 커버율 ≥ 60%: 녹색 "사전 양호"
→ 사용자가 "75분 짜리를 다시 돌려야 하나 5초짜리로 충분한가"를 UI에서 즉시 판단 가능

## 이 경험으로 체득한 설계 원칙

> **"채움의 가치는 데이터의 신선함에 달려 있다"**
> 분석 준비 상태 패널이 가치를 갖는 이유는 '예쁜 카드'여서가 아니다.
> 매 실행마다 자동으로 갱신되는 실제 데이터가 있기 때문이다.
> 정적인 채움은 빈 공간보다 나쁘다. 오래된 정보는 오해를 만든다.

> **"UI 변경의 전제 조건은 데이터 구조의 변경이다"**
> 이번 UI 개편의 실질적 작업은 `analysis_meta.json` 설계였다.
> UI는 데이터를 표시할 뿐이다. 표시할 데이터가 없으면 UI 변경은 공허하다.
