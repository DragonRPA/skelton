## 1. 개요 및 배경

PowerShell, 배치 파일, CLI 환경에서 백그라운드 태스크를 실행했을 때, **작업 목적이 이미 완료되었음에도 태스크가 종료 신호(EOF)를 반환하지 않고 큐(Queue)를 락(Lock) 걸어버려 다음 지시가 영구 중단되는 현상**이 지속적으로 발생함.

---

## 2. 4대 근본 원인 분석 (Root Cause)

1. **표준 입출력(stdout/stderr) 파이프 스트림 누수 (가장 흔함)**:
   - 메인 로직은 끝났으나 서브프로세스가 콘솔 파이프 핸들을 물고 있어 런타임이 프로세스를 RUNNING으로 오판.
2. **비가시적 인터랙션 대기 (Invisible Interactive Block)**:
   - 백그라운드 내부에서 Pager(`more`/`less`), `pause`, `Read-Host` 등 사용자 입력을 대기하여 영구 블로킹.
3. **자식/데몬 프로세스 잔존 (Zombie Children)**:
   - 부모 스크립트 종료 후에도 백그라운드 스레드가 남아 Windows 프로세스 트리가 닫히지 않음.
4. **비동기 대기시간 오판**:
   - 1~2초 단발성 명령을 `WaitMsBeforeAsync` 과소 설정(500ms)으로 억지 백그라운드 전환하여 큐 정체 유발.

## 3. 프로세스 멈춤 방지 5대 불변 규칙 (Zero-Hang Protocol)

```
[비인터랙티브 세션] ──► [출력 파이프 Detach] ──► [Pager 원천 무력화] ──► [타임아웃 Watchdog] ──► [동기 완결 우선]
 -NonInteractive        > task.log 2>&1          PAGER=cat                Wait-Job -Timeout       WaitMs: 3000~5000ms
 exit $LASTEXITCODE     핸들 즉각 반환          프롬프트 차단            초과 시 강제 사살       불필요 비동기 금지
```

1. **비인터랙티브 3대 플래그 및 `exit` 강제**:
   ```powershell
   powershell -NoLogo -NoProfile -NonInteractive -Command "& { <명령> ; exit $LASTEXITCODE }"
   ```
2. **출력 파이프 스트림 분리 (Pipe Detach)**:
   - 장기 백그라운드 작업은 콘솔 핸들을 쥐고 있지 않도록 `> task.log 2>&1` 또는 `$null`로 리다이렉트.
3. **터미널 페이저(Pager) 및 대기 프롬프트 무력화**:
   - `$env:PAGER = 'cat'`, `$env:GIT_PAGER = 'cat'` 환경변수 강제 및 `pause`/`Read-Host` 사용 일절 금지.
4. **타임아웃 워치독(Watchdog)**:
   - 백그라운드 잡 구동 시 `Wait-Job -Timeout <초>`를 설정하고 초과 시 `Stop-Job` ➔ `Remove-Job`으로 회수.
5. **에이전트 `WaitMsBeforeAsync` 최적화**:
   - 단발성 조회/빌드 명령은 `WaitMsBeforeAsync: 3000~5000ms`로 동기 완결 유도.
