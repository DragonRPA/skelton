## 1. 결정 배경 및 문제의식 (Why)

과거 데스크톱 로컬 에이전트 운용 과정에서 아래 3대 병목과 위험이 지속적으로 발생함:
1. **배포 바이너리 거대화 및 트래픽 낭비**:
   Node.js 런타임(약 80MB)을 단일 실행파일(SEA)로 번들링할 경우, 단 한 줄의 UI 수정이나 버그 패치에도 90MB 대형 실행파일 전체를 매번 재컴파일하고 사용자가 다시 다운로드해야 하는 심각한 비효율 발생.
2. **지적재산권(IP) 노출 및 위변조 위험**:
   스크립트 형태로 배포 시 사용자 PC의 `C:\eBroAgent\` 디스크에 회사의 핵심 업무 비즈니스 로직, API 연동 키, 알고리즘이 평문(Plaintext JavaScript)으로 적나라하게 노출되어 경쟁사 유출 및 무단 변조 위험에 직면함.
3. **업데이트 시 사용자 조작 마찰(Friction)**:
   버전 업데이트 때마다 사용자가 윈도우 제어판에서 기존 프로그램을 수동 삭제(Uninstall)하고 새 인스톨러를 실행해야 한다면, 전사 시스템 개발 표준 헌장 제1조(최대 편익 및 최소 조작 원칙)에 정면으로 위배됨.

## 2. 데스크톱 에이전트 4대 구성 원칙 (How)

### 2.1 2계층 분리 아키텍처 (Two-Tier Separation)
시스템은 불변의 **런타임 호스트(eBroHost)**와 가변의 **비즈니스 코어(engine.dat)**로 완전 물리 분리한다:
- **계층 1: 불변 런타임 호스트 (`eBroHost.exe`)**
  - Node.js V8 런타임, PE Subsystem 2 GUI 백그라운드 무소음 상주 프로세스, 포트(5175) 리스너, 시스템 트레이 아이콘 관리만 담당.
  - 비즈니스 로직이 전혀 포함되지 않으므로 런타임 버전이 바뀌지 않는 한 **수정 및 재배포 빈도 0%의 영구 불변 바이너리**로 유지.
- **계층 2: 가변 비즈니스 코어 (`core/engine.dat`)**
  - 모든 비즈니스 로직, REST API 엔드포인트, 외부 라이브러리(`xlsx`, `pdf-lib`, `nodemailer` 등)를 단일 번들로 인라인화하고 AES-256-GCM으로 암호화한 약 2MB의 독립 바이너리.

### 2.2 디스크 평문 노출 제로(Zero-Plaintext) 및 메모리 직접 실행
- 빌드 파이프라인(`encrypt_core.cjs`)에서 `esbuild`로 모든 의존성을 인라인 단일 JS로 압축 후, 32바이트 SHA-256 키 및 12바이트 랜덤 IV로 AES-256-GCM 암호화하여 `engine.dat`를 생성.
- `eBroHost`는 기동 시 `engine.dat`를 RAM으로 직접 읽어들여 인메모리에서 복호화한 후 Node.js V8 가상머신(`vm.runInThisContext`)에서 즉시 구동.
- **사용자 디스크에는 어떠한 평문 JavaScript 파일도 쓰지 않으며(0 Byte)**, 인증 태그(Auth Tag) 검증을 통해 파일이 1비트라도 위변조되면 기동을 즉시 거부함.

### 2.3 초경량 무소음 백그라운드 핫패치 (Lightweight Hot-Patch)
- UI 디자인 변경, 비즈니스 로직 추가, 버그 패치 발생 시 호스트 재설치 없이 `version.json`의 `coreUrl`을 통해 **약 2MB 크기의 `engine.dat`만 0.5초 만에 백그라운드 다운로드**.
- 다운로드 완료 즉시 백그라운드에서 호스트 프로세스를 1초 만에 무소음 재기동하여 패치를 적용. 사용자 화면에 검은색 콘솔 창이나 작업 방해 팝업을 일절 띄우지 않음.

### 2.4 인플레이스(In-place) 업그레이드 원칙
- 제어판 수동 삭제 절차를 영구 금지함.
- 인스톨러(`eBroAgent_Setup.exe`)는 단일 `AppId`를 바탕으로 실행 중인 기존 프로세스를 안전하게 종료하고, 동일 디렉토리에 파일만 즉시 덮어쓰는 인플레이스(In-place) 업그레이드를 완결함.

## 3. 온디바이스 AI 엔진(Ollama/Whisper/VLM) 배포 거버넌스

### 3.1 3대 배포 전략의 검토 및 채택/반려 확정
1. **[채택] 제1안: 기본 설치 단계 부트스트랩 (Bootstrap)**
   - 인스톨러(`eBroAgent_Setup.exe`) 실행 시 로컬 PC에 Ollama 런타임 설치 여부를 자동 탐색하고, 미설치 환경에 대해 무소음(Silent `/VERYSILENT`) 자동 설치를 연계함.
2. **[채택] 제2안: 단계적 백그라운드 스트리밍 다운로드 (On-demand/Lazy Stream)**
   - 초기 설치 시 수 기가바이트(GB) 모델을 묶어서 배포하지 않고, 에이전트 설치 완료 후 백그라운드 데몬이 우선순위에 따라 순차적으로 스트리밍 다운로드 및 로컬 등록을 집행함.
     - 1순위: 텍스트 LLM (`ebro-qwen:3b`, 약 2.0GB)
     - 2순위: 음성인식 STT (`Whisper-base/small`, 약 150~500MB)
     - 3순위: 비전 멀티모달 VLM (하드웨어 VRAM 6GB+ 감지 PC 선별 배포)
3. **[영구 반려] 제3안: 사내 P2P / 로컬 캐시 릴레이 (Local P2P Relay)**
   - **반려 사유**: 기업 보안 인프라는 방화벽, 서브넷 격리, 사내 포트 차단, 폐쇄망 등 P2P 통신을 엄격히 통제함. P2P 시도 시 보안 솔루션 오탐지(악성코드 의심) 및 네트워크 장애 유발 위험이 크므로 전면 배제함.

### 3.2 사내 파인튜닝 모델(`ebro-qwen:3b`) 호스팅 및 배포 저장소 표준
- **표준 저장소**: **Cloudflare R2 Object Storage (Private Bucket)**
- **선정 배경**:
  1. **Egress(다운로드 트래픽) 비용 0원**: 기가바이트 단위 AI 모델 배포 시 AWS S3 대비 네트워크 전송 비용이 완전 면제됨.
  2. **지적재산권(IP) 완벽 차단**: Ollama.com(퍼블릭 전용)과 달리 버킷을 비공개(Private)로 유지하여 경쟁사 유출을 원천 방지.
  3. **Presigned URL 일회용 서명 배포**: eBroAgent가 인증 서버로부터 30분 유효기간의 서명된 URL을 동적으로 발급받아 `ebro-qwen-3b.gguf`를 조용히 스트리밍 수신 후 로컬 Ollama에 등록(`ollama create ebro-qwen:3b -f Modelfile`).

## 4. 정량적 성과 및 보존 법칙 검증

| 지표 | 과거 단일 대형 방식 | 2계층 분리 + 핫패치 신규 체계 | 개선 효과 |
|---|---|---|---|
| **일상 업데이트 배포 용량** | 98.7 MB (전체 재설치) | **2.1 MB (`engine.dat`)** | **97.8% 트래픽 절감** |
| **클라이언트 다운로드 시간** | 15초 ~ 40초 | **0.5초 ~ 1.2초** | **초고속 무체감 적용** |
| **디스크 소스코드 노출** | 평문 JS 다수 노출 | **0 Byte (AES-256-GCM 메모리 로드)** | **지적재산권 100% 보호** |
| **사용자 조작 단계** | 제어판 삭제 ➔ 재설치 (5단계) | **무조작 백그라운드 자동 적용 (0단계)** | **최대 편익(규칙 1.1) 달성** |
