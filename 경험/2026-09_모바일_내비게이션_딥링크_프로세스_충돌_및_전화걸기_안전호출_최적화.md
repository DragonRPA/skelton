# 모바일 내비게이션 딥링크 프로세스 충돌(스마트폰 멈춤) 원인 분석 및 안전 호출 최적화 경험

- **작성일자**: 2026-09-04 13:00
- **프로젝트**: 기연리프트 ERP (`Kiyuen_Lift`)
- **관련 커밋/버전**: v1.3.0.Build.117

---

## 1. 증상 및 현상 (Symptom)
- 스마트폰 모바일 화면에서 **[TMAP 길안내]** 버튼을 누르자 TMAP 앱이 실행되다가 중간에 멈추며, 스마트폰 전체가 먹통(소프트 브릭 / 터치 불가) 상태로 락업됨.
- 스마트폰 강제 재부팅(`전원 + 볼륨다운`) 후에야 정상 복구됨.
- "혹시 전화걸기(`tel:`) 호출도 동일한 위험이 있는지?"에 대한 전수 검증 요청 발생.

---

## 2. 근본 원인 분석 (Root Cause Analysis)

### 🔴 1) TMAP 길안내 폰 멈춤의 결정적 원인: `setTimeout(window.open, 1500)` 비동기 이중 인텐트 충돌
- 기존 코드(`MobileAsDetail.tsx`):
  ```typescript
  const handleOpenTmap = () => {
    const destination = ...;
    window.location.href = `tmap://search?name=${encodeURIComponent(destination)}`;
    setTimeout(() => {
      window.open(`https://map.kakao.com/link/search/${encodeURIComponent(destination)}`, '_blank');
    }, 1500);
  };
  ```
- **치명적 메커니즘**:
  1. `window.location.href = tmap://...`이 실행되면 안드로이드 OS는 브라우저(Chrome/PWA)를 일시 중지(Pause)하고 TMAP 앱을 포그라운드로 올리는 프로세스 전환(Activity Transition)을 시작함.
  2. TMAP 앱이 막 3D 렌더링 엔진과 GPS 하드웨어를 초기화하는 **1.5초 직후, 브라우저 백그라운드 타이머가 강제로 `window.open`을 격발**함.
  3. 백그라운드로 밀려난 브라우저가 다시 새 팝업 창과 카카오맵 인텐트를 포그라운드로 띄우려고 시도함.
  4. 안드로이드 시스템의 `ActivityTaskManager`와 `SurfaceFlinger`(윈도우 매니저)는 두 개의 서로 다른 태스크(`com.skt.tmap.ku` vs `com.android.chrome`)가 포그라운드 제어권과 하드웨어 화면 권한을 동시에 차지하려는 **교착 상태(Deadlock / Focus Lockup / ANR)**에 빠짐.
  5. 그 결과 터치 이벤트 큐(InputQueue)와 렌더러가 완전히 얼어붙어 스마트폰 전체가 벽돌 상태가 됨.

### 🟡 2) 안드로이드 Chrome 표준 Intent 미준수
- 안드로이드 환경에서는 단순 `tmap://` 커스텀 스킴 대신, 공식 표준인 `intent://` 스킴과 `package=com.skt.tmap.ku`, 그리고 미설치 시 자동 이동하는 `S.browser_fallback_url`을 지정해야 OS 레벨에서 충돌 없이 단일 트랜잭션으로 처리됨.

### 🟢 3) 전화걸기(`tel:`)는 안전한가?
- 전화걸기는 `setTimeout` 이중 호출이 없으므로 **TMAP과 같은 프로세스 충돌 락업은 발생하지 않음**.
- 그러나 `window.location.href = 'tel:...'`을 직접 대입하면 일부 PWA/웹뷰 환경에서 현재 웹 화면이 `ERR_UNKNOWN_URL_SCHEME` 흰색 에러를 내거나 세션이 리셋될 위험이 있음.
- 따라서 전화걸기도 DOM 임시 `<a>` 태그 클릭 방식으로 다이얼러를 호출해야 100% 안전함.

## 3. 영구 해결 조치 (Permanent Fix)

1. **`src/utils/nativeLauncher.ts` 중앙 전담 모듈 신설**:
   - **타이머 완전 영구 제거**: 어떠한 경우에도 `setTimeout`을 통한 강제 백그라운드 팝업을 금지.
   - **안드로이드 표준 Intent 스킴 적용**:
     ```text
     intent://search?name=${dest}#Intent;scheme=tmap;package=com.skt.tmap.ku;S.browser_fallback_url=${fallbackUrl};end;
     ```
     - TMAP 설치 시: OS가 TMAP을 직접 단독 실행 (브라우저 간섭 0).
     - TMAP 미설치 시: OS가 fallbackUrl(웹 지도)을 브라우저 새 창으로 단독 연결.
   - **iOS 사파리 전용 스킴 분기**: `tmap://search?name=${dest}`로 안전 실행.
   - **DOM `<a>` 태그 클릭 위임**: `window.location.href` 직접 이동 대신 숨김 `<a>` 엘리먼트 클릭으로 브라우저 탐색 실패 방지.
2. **`safePhoneCall` 헬퍼 전면 적용**:
   - 전화번호 숫자 정제(`replace(/[^0-9+*#]/g, '')`) 후 가상 앵커 클릭으로 다이얼러 호출.
3. **`MobileAsDetail.tsx` & `FieldAsManagement.tsx` 전면 교체**:
   - TMAP뿐만 아니라 카카오내비, 네이버지도 원터치 선택 및 기억 기능 완비.

---

## 4. 교훈 (Key Learnings)
- **모바일 웹/PWA에서 네이티브 앱 딥링크 호출 시, 미설치 대비용 `setTimeout` 폴백은 "스마트폰을 멈추게 하는 치명적인 폭탄"이다.**
- **앱 설치 여부 판별과 폴백은 자바스크립트 타이머가 아닌, 모바일 OS의 Intent `S.browser_fallback_url`에 100% 위임해야 한다.**

## 5. 추가 발견 및 2차 완성 (Build.129 - 2026-09-04 15:15)

### 🔴 1) 장소찾기(search) 모드 오작동 및 백그라운드 재진입 시 벽돌(Deadlock) 재발
- **현상**:
  - `intent://search?name=...`은 길안내(내비게이션)가 아니라 단순 통합검색(장소목록) 화면으로 열림.
  - T맵이 이미 실행(백그라운드 상주) 중인 상태에서 크롬으로 돌아와 다른 장소의 길안내를 다시 시도하면, 핸드폰 전체가 또다시 벽돌(재부팅 필요)이 됨.
- **근본 원인 규명**:
  1. `S.browser_fallback_url`의 치명적 레이스 컨디션:
     - T맵이 백그라운드에서 깨어나는 동안(수백 ms), 크롬의 Intent 처리기가 "앱 즉시 실행 지연"으로 오판하여 fallback 웹페이지를 크롬 내부에서 동시에 로드함.
     - T맵의 SurfaceView와 크롬의 WebContents가 안드로이드 WindowManagerService(WMS) 화면 점유 포커스를 동시에 획득하려다 SurfaceFlinger Lock 데드락 발생.
  2. 기사의 연타/더블탭 시 Intent Flood로 안드로이드 Task Stack 붕괴.

### 🟢 2) 최종 완성 조치:
1. **정식 길안내(Route) 스킴 전환**:
   - Android: `tmap://route?referrer=com.skt.Tmap&goalname=${encodedDest}`
   - iOS: `tmap://route?goalname=${encodedDest}`
   - 카카오내비: `kakaonavi://navigate?name=${encodedDest}&coord_type=wgs84`
   - 네이버지도: `nmap://navigation?dname=${encodedDest}&appname=com.kiyuen.lift`
2. **`S.browser_fallback_url` 100% 영구 퇴출**:
   - 백그라운드 앱과의 포그라운드 경합 원천 차단.
3. **2초 디바운스 락 (Navigation Debounce Lock)**:
   - 기사의 연타나 빠른 재호출 시 OS 인텐트 폭풍 방어.
4. **현장 마스터 정밀 도로명/지번 주소 1순위 자동 매핑**:
   - `ticket.siteId` 기반 `db.customerSites`의 정밀 주소(`address`) 우선 공급으로 100% 정확한 길안내.
