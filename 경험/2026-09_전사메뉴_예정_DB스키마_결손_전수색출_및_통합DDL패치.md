## 1. 배경 및 문제의 본질
모바일-PC 전수 대조 감사(Build.166)가 성공적으로 완결된 직후, 각 메뉴 화면(영업, 계약, 배차, 출고, 입고, 정비, 소모품, 회계, 채권 등)이 비즈니스 라이프사이클 상 요구하는 모든 데이터 필드가 중앙 원격 PostgreSQL DB(Supabase) 및 단일 원본 DDL(`schema.sql`)에 완벽히 구축되어 있는지에 대한 전수 점검 요구가 제기되었다.

실제 점검 결과:
1. **테이블 레벨 결손 및 네이밍 불일치**:
   - `legal_notice_logs` (내용증명 발송 감사 대장), `legal_notice_templates` (최고장 템플릿)가 원격 DB 및 `schema.sql`에 완전히 부재.
   - `external_leases` (전대/임차 장비 계약) 및 `consumable_purchases` (소모품 구매 관리)가 원격 DB에는 존재하나 `schema.sql`에서 누락.
   - `bank_initial_balances` vs `bank_account_initial_balances`: `db.ts`는 `bank_initial_balances`로 쿼리하고 원격 DB는 `bank_account_initial_balances`로 생성되어 캐시 미스 발생.
   - `asset_inout_logs` vs `asset_in_out_logs`: 네이밍 언더바 불일치 및 구버전 CHECK 제약조건으로 인한 `INBOUND_CANCEL` 등 롤백 트랜잭션 차단 위험.
2. **컬럼 레벨 결손 (72개 속성 누락)**:
   - `customers`의 `bizType`, `bizItem`, `transactionStatus` (ALLOWED/BLOCKED 출고제한).
   - `deliveries`의 `reconciliationStatus`, `costAdjustmentReason`, `vehicles`, `dispatchCategory`의 `'교환'`(EXCHANGE) 미등록.
   - `repairs`의 `targetAssetStatus`, `siteAddress`, `inspectionItemCode`, `degradationScore`, `consumables`, `timelineEvents`.
   - `assets`의 `maintenanceScore`, `billingDay`, `monthlyRentalFee`, `dailyRentalFee`, `disposalDate`, `disposalPrice`, `fullDefectSummary`.
   - `users`, `contracts`, `billings`, `annual_leave_quotas`, `overtime_records`, `payroll_closings`, `bank_transactions`, `google_configs`, `prepaid_transactions`, `delinquency_action_logs` 전반의 결손.

## 2. 해결 절차 및 아키텍처 구현

### 1단계: 실증적 전수 교차 검증 (Empirical Cross-Audit)
- 정적 코드 분석(`src/` 전수 스캔)으로 47개 컬렉션 / 63개 테이블 목록 추출.
- Supabase REST API를 동적 호출하여 각 테이블 및 컬럼의 실제 존재 여부를 쿼리 레벨에서 직접 판정.
- `schema.sql` AST/정규식 파싱을 통해 Master DDL과 TypeScript 인터페이스 간 1:1 완벽 대조.

### 2단계: 독립 실행형 통합 DDL 패치 (`scripts/patch_v1_4_0_schema_deficiencies.sql`)
- **완전한 멱등성(Idempotency)**: `CREATE TABLE IF NOT EXISTS`, `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 적용.
- **제약조건 안전 갱신**: `DROP CONSTRAINT IF EXISTS` 선행 후 `ADD CONSTRAINT`로 교체하여 기존 데이터 손상 없이 갱신.
- **하위 호환 뷰(VIEW) 및 데이터 동기화**: `asset_in_out_logs` 및 `bank_account_initial_balances` 뷰 생성, 레거시 테이블 잔류 데이터 무손실 복사.
- **전사 RLS 전면 비활성화 및 무제한 권한 부여 (헌장 5.3)**: `anon`, `authenticated` 롤에 대한 무제한 CUD 보장.

### 3단계: Master SSOT `schema.sql` 최신화
- `schema.sql`에 신규 테이블 6종 및 20개 테이블의 모든 결손 컬럼, 한글 주석, 제약조건을 100% 통합.
- CRLF/LF 정규화를 적용하여 Windows 환경에서의 치환 오류 원천 방지.

### 4단계: 클라이언트 코어 엔진 (`src/services/db.ts`) 무결점 방어 가드
- `fetchAllRowsFromSupabase`, `insertRow`, `updateRow`, `deleteRow`에서 `bank_initial_balances` 및 `asset_inout_logs` 테이블 미반영 Supabase 환경에서도 구버전 테이블명으로 자동 Fallback 동작하도록 이중 안전망 구축.
- `normalizeKey`에 상호 호환 키 매핑 등록 (`bank_account_initial_balances` ➔ `bankInitialBalances`, `asset_in_out_logs` ➔ `assetInOutLogs`).

## 3. 핵심 성과 및 검증 결과
1. **테이블 및 인터페이스 100% 일치**: 47개 컬렉션 전수 1:1 DDL 매핑 완성, 결손 인터페이스 컬럼 0건 달성.
2. **빌드 무결성**: `cmd /c "npm run build"` (`tsc -b && vite build`) 0 Type Error 무결점 통과 (`✓ built in 872ms`).
3. **무음 실패(Silent Failure) 원천 방어**: DDL 패치가 아직 실행되지 않은 원격 DB 환경에서도 클라이언트 fallback이 동작하여 어떤 비즈니스 메뉴에서도 데이터 누락이나 충돌 없이 완벽 동작.
