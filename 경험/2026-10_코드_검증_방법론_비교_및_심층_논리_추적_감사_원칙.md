## 1. 개요 및 배경

본 문서는 이전 세션에서 수행된 두 AI 에이전트(초기 제미니 기반 감사관과 직전 클로드 기반 감사관)의 코드 검증 방식을 비교·식별하고, 향후 당사 시스템의 결함 검증 및 개발에 적용해야 할 방법론을 정립하기 위해 작성되었다.

단순히 문자열이 파일에 존재하는지만 훑고 면죄부(PASS)를 발행하던 요식 감사에서 벗어나, **함수 내부의 조건 분기, 호출 체인, 상태 머신의 역행 및 3대 보존 법칙을 끝까지 추적하는 심층 논리 감사 체계**를 확립한다.

## 2. 검증 방식의 근본적 차이점

| 구분 | 초기 검증 방식 (Gemini / Part 1~3 Auditors) | 직전 검증 방식 (Claude / Line-level Auditor) |
| :--- | :--- | :--- |
| **핵심 접근법** | 표면적 문자열 스캔 (Shallow Grep Scan) | 심층 논리/실행 흐름 추적 (Deep Logical Tracing) |
| **주요 사용 도구** | `Select-String`, `cat` (정규식 기반 텍스트 필터링) | `view_file` (코드 블록/함수 본문의 문맥 기반 읽기) |
| **상태(Status) 검증** | 특정 상태값이나 Enum 문자열이 파일 내에 물리적으로 존재하는지만 확인 | 분기문(`if`), 에러 처리, 연쇄 호출 등 런타임의 **실제 할당 흐름과 인과율**을 확인 |
| **의존성 및 부수 효과** | UI 라벨의 유무에만 집중하여 부수 효과를 검증하지 못함 | 권한(Gating), 상태 변이, DB 이력 기록, 태스크(ToDo) 등 2차 부수 효과(Side-effect)를 전수 검증 |
| **결함 적발 능력** | 단순 오탈자 및 라벨 누락 검출에 유리하나, 논리적 버그 적발 실패 | G-29, G-30, G-31과 같은 **"비즈니스 로직 우회 및 역행 결함"**을 정확히 적발 |
| **Drift(변형) 대응** | 코드 라인 번호가 변동되면 검증 실패 확률이 높음 | 라인 번호가 변동되어도 함수명과 로직을 추적하여 능동적 대응 |

## 3. 클로드(Claude)의 검증 방식 분석

직전에 투입된 클로드는 단순히 문서에 적힌 라벨을 찾는 데 그치지 않고, **실제 렌탈 도메인 헌장(전사 개발 표준 헌장)에 기반한 적대적(Adversarial) 감사**를 수행했다.

1. **End-to-End 인과율 추적**: UI 버튼의 핸들러(예: `handleAddBasketToExistingContract`)에서 시작해, 내부 컨텍스트(`AppContext.tsx`)의 함수(예: `cancelPayment`)로 이어지는 뎁스를 끝까지 파고들었다.
2. **보존 법칙(Conservation Law) 점검**: 상태가 `REQUESTED`(발송완료)인 청구가 수납 취소 시 `UNPAID`로 잘못 회귀하여 인과율이 붕괴되는 현상(G-30)이나, 부분 결제 시 부모 상태가 잘못 상속되는 논리적 모순을 적발했다.
3. **권한 및 방어 코드(Guardrails) 실사**: 자산 매각 시 `ASSIGNED`(출고대기) 장비가 실수로 매각될 가능성(G-25)이나 UI에서 상태를 강제로 우회하여 수정할 가능성(G-29) 등 "시스템이 막아주고 있는가?"를 실질적으로 검증했다.

## 4. 학습 및 글로벌 정책 적용 선언 (Methodology Internalization)

우리는 위에서 식별된 **"심층 논리 추적(Deep Logical Tracing)"** 방법론을 완벽히 학습 및 내재화하여 전사 표준 헌장에 반영한다:

1. **No More Blind Grep (문자열 단독 검색 면죄부 발행 전면 금지)**:
   - 단순히 `grep`이나 `Select-String`으로 키워드가 파일 안에 있다는 이유만으로 합격(PASS) 판정을 내리는 요식 행위를 영구 엄단한다.
2. **Context-Aware Verification (`view_file` 기반 본문 실사)**:
   - 반드시 `view_file`을 통해 함수 본문 전체의 흐름(조건문, 분기, 리턴 값, 트랜잭션, 예외 처리)을 직접 눈으로 읽고 검증한다.
3. **Domain Penetration (3대 보존 법칙 및 인과율 관통 검증)**:
   - 전사 시스템 개발 표준 헌장 제5장에 명시된 3대 보존 법칙(날짜 보존, 수지 보존, 상태 보존)과 사법적·회계적 귀속선이 실제 코드의 실행 결과와 100% 일치하는지 논리적 인과율을 따져 비판적으로 검증한다.
