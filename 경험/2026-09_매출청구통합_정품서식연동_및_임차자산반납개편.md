# 2026-09 매출 청구 통합 정품 서식 연동 및 임차자산 반납 개편

## 1. 개요 및 배경
- 시스템 버전: `v1.12.0.Build.42` (2026-09-10 02:45)
- 사장님 지시: 매출 청구 통합에서 개별 거래명세서 대비 정품 엑셀/PDF 생성 구조 확립, UI 깨짐 정상화, 가상 더미 텍스트 제거, 통합 청구 시 기존 청구 2배 부풀림 여부 검증 및 임차자산 수정/반납 체계 전면 정립.

## 2. 주요 해결 내역
1. **매출 청구 통합 거래명세서 정품 양식 주입 파이프라인**:
   - 임시 json_to_sheet를 폐기하고 당사 정품 마스터 서식(00.거래명세서양식.xlsx)을 불러와 ExcelJS로 11행 셀과 공급자/공급받는자/계좌를 정확히 치환·주입하는 정품 엑셀 생성 및 로컬 COM 에이전트 연동 A4 PDF 다운로드 탑재.
   - 가짜 상호((주)기은리프트) 및 (가상) 품목 텍스트를 제거하고 전사 SSOT(주식회사 기연리프트, 대표 이수용, 사업자번호 138-81-83251, 계좌 신한은행 140-010-007060)로 전면 동기화.
   - 11행 그리드 컬럼 폭 고정 및 줄바꿈 방지 적용으로 UI 깨짐 완전 해소.
2. **청구서통합 ➔ 청구총액 2배 부풀림 방지 및 개별 청구 대장 연동**:
   - billings(원천 청구)와 billing_invoices(통합 묶음)는 1:N 외래키(invoiceId)로 상호 연결 관리되므로 DB 상 청구 총액이 2배로 중복 계상되지 않음을 검증.
   - 개별 청구 대장(Billings.tsx Tab 2) 각 행에 [통합: {b.invoiceId}] 배지 부여, 발송 버튼에 [개별발송] 안내, 상세 카드에 통합 인보이스 안내 배너 및 필터바에 통합 구분 (전체/단독/통합) 드롭다운 신설.
3. **임차자산 수정 모달 결함 해소 및 반납 체계 정립**:
   - vendorId만 존재하고 renter 필드가 비어있던 자산(H2591)의 락 결함을 양방향 역추적 매핑으로 해결.
   - 현장 대여중(status === 'RENTED') 자산도 반납 버튼([직반납])을 활성화하고, [현장 ➔ 임차처 직반납] vs [주기장 ➔ 임차처 반납] 분기 지원.
4. **계약현황 엑셀 17열(공장입고일) 오인 반납 506대 자산 원격 DB 복원**:
   - 17열 공장입고일을 반납일로 오인 파싱하여 반납 처리되었던 Supabase 내 506대 자산의 actualRentReturnDate = null, status = 'RENTED' 일괄 정상화 복원 완료.

## 3. 체득 원칙
- 마스터 엑셀 파싱 시 컬럼의 물리적 명칭뿐 아니라 실무 도메인 의미(공장입고일 vs 현장반납일)를 철저히 검증하여 자산 상태를 왜곡하지 않아야 함.
- 1:N 집계 인보이스 도입 시 원천 청구 테이블과 집계 테이블의 외래키 연동을 명시하고, 개별 화면에 통합 식별 배지를 상시 표출하여 실무자의 중복 청구 착오를 원천 차단함.
