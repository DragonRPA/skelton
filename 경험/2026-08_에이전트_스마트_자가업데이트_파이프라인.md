# 🔬 [경험] 에이전트 스마트 자가업데이트 4단계 파이프라인

- **일시**: 2026-08-19 13:54 (KST)
- **작성자**: DragonRPA AI / 시스템 총괄
- **대상 시스템**: DragonRPA Agent & 웹 프론트엔드 통신 파이프라인

---

## 1. 배경 및 맥락
- 웹 프론트엔드에서 로컬 PC 에이전트의 버전을 비교 감지하여 [스마트 업데이트] 버튼을 제공하고 있었으나, 업데이트 실행 후 구버전 프로세스 잔존 또는 파일 잠금으로 인하여 갱신 실패 및 라벨 출력 중단 문제가 발생함.
- 에이전트 단일 실행 파일이 150MB를 초과하여 GitHub 원격 배포 용량 제한(100MB)에 걸리는 문제 발생.

---

## 2. 핵심 발견 및 해결 (4단계 논스톱 파이프라인)
1. **180KB 초경량 네이티브 컴파일**:
   - `SelfContained=false` 및 `PublishSingleFile=true` 조합을 적용하여 기존 154MB에서 180KB로 파일 크기를 99.8% 절감함.
   - GitHub 푸시 및 웹 다운로드 속도가 1초 이내로 단축됨.
2. **원자적 4단계 자가 업데이트 파이프라인**:
   - `1단계 (안전 다운로드)`: 기존 에이전트가 살아있는 상태에서 `.new` 파일로 먼저 다운로드.
   - `2단계 (확실한 프로세스 Kill)`: 다운로드 성공 검증 후 `taskkill /f /im UBUS_DragonRPA_Agent.exe`로 점유 프로세스 강제 종료.
   - `3단계 (파일 교체)`: 파일 락 해제 후 `move /y`로 원본 exe 교체.
   - `4단계 (자동 재실행)`: `start`로 새 에이전트 구동 및 임시 배치 자동 자폭.

---

## 3. 재발 방지 및 교훈
- 실행 중인 Windows 바이너리를 교체할 때는 항상 독립된 래퍼 스크립트(.bat)에서 `taskkill` 선행 후 `move /y`를 수행해야 파일 점유 거부(Access Denied) 오류를 원천 차단할 수 있다.
- .NET 8 데스크톱 환경에서는 `SelfContained=false`를 적극 활용하여 배포 바이너리 용량을 극도로 가볍게 유지한다.
