## 2. 구체적 구현 계획 및 데이터 모델

### ① DB 스키마 확장 (`src/services/db.ts`)
1. **`LegalNoticeLog` (내용증명 발송 이력 테이블)**:
   - `id`: string
   - `customerId`: string
   - `customerName`: string
   - `representative`: string
   - `address`: string
   - `overdueAmount`: number
   - `overdueDays`: number
   - `noticeTitle`: string
   - `noticeContent`: string (발송 당시의 편집된 본문 전문)
   - `deadlineDays`: number (변제 최고 기한: 기본 7일)
   - `sentDate`: string (발송 일자)
   - `sentByUserId`: string (발송 경영진 ID)
   - `sentByName`: string (발송 경영진 이름)
   - `postalTrackingNo?: string` (우체국 등기번호)
   - `createdAt`: string
2. **`LegalNoticeTemplate` (내용증명 기본 서식 커스텀 테이블)**:
   - `id`: string
   - `templateName`: string
   - `title`: string
   - `content`: string
   - `updatedAt`: string

### ② 경영진 고유 권한 통제 (Executive Prerogative Guard)
- `const isExecutive = currentUser?.role === 'ADMIN' || currentUser?.role === 'EXECUTIVE';`
- 내용증명 작성, 서식 편집, 발송 승인 버튼은 **오직 경영진에게만 활성화**.

### ③ 인라인 내용증명 스튜디오 (`src/pages/DelinquencyPage.tsx`)
- 좌측: 4대 법률 골격 표준 서식 기반 실시간 편집기 (변제 기한, 최고 금액, 조항 직접 수정, [기본 서식으로 저장] 기능).
- 우측: 우체국 내용증명 규격(상하좌우 20mm 여백, 기연리프트 직인 날인) 실시간 A4 프리뷰 및 인쇄(`Ctrl+P` / PDF 출력).
- 발송 실행 시:
  - `legalNoticeLogs`에 전문 및 발송자 저장.
  - `delinquencyActionLogs`에 `actionType: 'NOTICE_SENT'` 동시 기록.

### ④ 고객관리 화면 연동 (`src/pages/Customers.tsx`)
- 고객 목록 테이블: 내용증명 발송 거래처에 `📜 내용증명 N건` 배지 노출.
- 고객 상세 뷰: **[내용증명 발송 이력]** 섹션을 탑재하여, 과거 발송 일자, 최고 금액, 당시 발송된 전문 문서 열람 모달 지원.
