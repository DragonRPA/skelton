## 1. 목적 및 핵심 목표
1. **Whisper STT와의 VRAM 평화적 공존**: 총 VRAM 3GB 이내로 실시간 STT와 로컬 LLM Fallback 동시 무중단 구동.
2. **응답 지연시간 10배 단축**: 기존 7B 모델의 1.5~3.0초 지연을 **100~200ms**로 단축하여 실시간 전화 응대 최적화.
3. **부품코드 18종 및 증상 분류 정확도 90% 이상 확보**.
4. **JSON 무결성 100% 보장**: Pydantic 스키마 및 Ollama JSON 모드 결합으로 파싱 에러 0건 유지.

---

## 2. 단계별 실행 계획 (Phase 1 ~ Phase 4)

### Phase 1: 특수 도메인 데이터셋 구축 파이프라인 (Data Prep)
- **데이터 소스**:
  - `symptom_rules` 테이블 키워드(50여 개) 및 18종 부품코드
  - A/S 상담 매뉴얼 및 실제 통화 발화 패턴 데이터
- **데이터 증강(Augmentation)**:
  - 구어체, 방언, 고객 불만 어조, 축약어 변형 템플릿 적용 (약 2,000건 생성)
- **포맷**: Qwen2.5 ChatML 기반 JSONL
  ```json
  {
    "messages": [
      {"role": "system", "content": "너는 바닥 청소장비 A/S 상담 전문 분류기다. 고객의 발화에서 핵심 증상 키워드와 18개 표준 부품코드(POWER, SUCTION, WATER_SOLENOID, DRIVE_BRUSH 등)를 식별하여 오직 JSON 형식으로만 답하라."},
      {"role": "user", "content": "바닥에 세정수가 전혀 안 흘러나와요. 밸브에서 딸깍 소리도 안 나고요."},
      {"role": "assistant", "content": "{\"keyword\": \"세정수 미공급\", \"part_code\": \"WATER_SOLENOID\"}"}
    ]
  }
  ```

### Phase 2: Unsloth + QLoRA 로컬 파인튜닝 (Training)
- **베이스 모델**: `unsloth/Qwen2.5-0.5B-Instruct` (약 4.9억 파라미터)
- **기법**: 4-bit QLoRA (Rank 16, Alpha 16, Target Modules: all linear)
- **환경**: 로컬 GPU (RTX 3060/4060) 또는 WSL2 환경 (VRAM 3GB 이하 사용)
- **학습 시간**: 약 300~500 steps (약 15분~25분 소요 예상)

### Phase 3: GGUF 양자화 변환 및 Ollama 패키징 (Deployment)
- **양자화**: `q4_k_m` (파일 크기 ~380MB 내외)
- **Modelfile 작성 및 Ollama 로컬 빌드**:
  ```dockerfile
  FROM ./space-advisor-qwen0.5b-q4_k_m.gguf
  PARAMETER temperature 0.1
  PARAMETER top_p 0.9
  ```
- Ollama 모델 등록: `ollama create space-advisor-slm -f Modelfile`

### Phase 4: 백엔드 연동 및 A/B 정량 벤치마크 (Evaluation)
- `backend/app/core/config.py`의 `ollama_model`을 `space-advisor-slm`으로 전환.
- `backend/app/api/v1/endpoints/counsel.py`에서 기존 `exaone3.5` 대비 4대 지표 측정:
  1. 지연시간(Latency ms)
  2. VRAM 점유량(MB)
  3. 분류 정확도(Hit Rate %)
  4. JSON 파싱 실패율(Error Rate %)

## 3. 리스크 및 대응 방안
- **Sub-1B 모델의 한국어 지시 준수력 한계 가능성**:
  - 만약 0.5B 모델이 복잡한 문맥에서 부품코드를 혼동할 경우, 즉시 1.5B 모델(`Qwen2.5-1.5B-Instruct`, 양자화 1.1GB, VRAM 1.5GB)로 스케일업(2단계 비교 검증) 수행.
