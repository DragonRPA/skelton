# 프로세스 단계별 업무 인계 ToDo 자동 발생 및 자동 상계 파이프라인 구축 (WTT 20회 관통 검증)

## 1. 개요 및 목적
- **목적**:
  고소작업대 렌탈 전 비즈니스 체인(영업 ➔ 배차 ➔ 주기장 출고검수 ➔ 운송기사/현장하차 ➔ 현장 AS ➔ 유상수리 청구 ➔ 회수 반납 ➔ 입고검수/정비 ➔ 단일 EXCHANGE ➔ 정기청구 ➔ 수납/연체 ➔ 매입정산 ➔ 자산매각 ➔ 소모품구매 ➔ 근태인사)의 각 단계에서 다음 업무 수행자에게 **물리적 ToDo가 100% 자동 발생**하고, 후속 조치 완료 시 **원자적 자동 상계(Auto-Clearance)**되는 엔터프라이즈 업무 인계 파이프라인을 구축하고 WTT 20회 도메인 관통 스트레스 테스트를 통해 완전 무결성을 검증합니다.
- **배경 및 문제점**:
  - 기존 시스템은 WebSocket 실시간 브로드캐스트(`broadcastWorkNotification`)와 대시보드 공용 집계 카드에 의존하여, 오프라인 시 메시지 유실, 개인화된 책임 ToDo 부재(핑퐁 방치) 현상이 발생하고 있었습니다.
  - 물리적 `todos` 테이블은 신규고객 정보미비(`MISSING_INFO`)와 연체 지시(`GENERAL`) 단 2곳에서만 한정 생성되어 15대 핵심 프로세스 중 14개 구간에서 ToDo 발생이 누락되어 있었습니다.
- **적용 표준**:
  - 전사 시스템 개발 표준 헌장 카테고리 I (최대 편익, 3대 핵심 가치, 출고검수 승인 시 RENTED 전환)
  - 카테고리 II (영업-출고 R&R 엄격 분리, 계약 속성 100% 상속, 단일 EXCHANGE 배차 1건 발행)
  - 카테고리 III (직무 중심 ToDo 피드 대시보드, 무수식어 건조 UI, 상하 스택, Gutenberg Z-패턴)
  - 카테고리 V (무음 실패 방지 `awaitPendingWrites`, WTT 5대 축 20회 관통 검증)

## 2. 사용자 검토 및 결정 필요 사항 (User Review Required)

> [!IMPORTANT]
> **핵심 아키텍처 결정 사항**:
> 1. **2-Tier 하이브리드 인계 모델**:
>    - **Tier 1 (공용 작업대 Pull Queue)**: 부서 전체의 물량(미배차, 출고대기, 미수리)을 고밀도 그리드에서 한눈에 조망.
>    - **Tier 2 (개인화 책임 Push ToDo)**: 로그인한 사용자 본인에게 직접 지정되었거나 본인 직무/부서의 당면 과제만 대시보드 ToDo 피드에 노출.
> 2. **1-Way 업무 라이프사이클**:
>    - 실무자의 임의 수기 체크/삭제를 금지하고, 실제 비즈니스 액션(배차 확정, 검수 승인, 수리 저장, 청구 바인딩) 완료 시 시스템이 ToDo를 자동 상계(`isCompleted: true`, `completionAction`) 처리.
> 3. **스키마 하위 호환성 100% 유지**:
>    - 기존 `todos` 테이블 구조를 보존하면서 `targetDept`, `targetRole`, `assignedUserId`, `taskCategory`, `priority`, `actionUrl`, `entityType`, `entityId`를 추가하여 기존 데이터 손상 없이 무중단 마이그레이션.
