## 1. 후회의 발단 (What went wrong)

- 기계(AI/OCR)는 이미지가 90도 기울어져 있든 180도 뒤집혀(상하반전) 있든 메모리 상에서 회전하여 텍스트를 인식하고 100건 전수 추출을 완결했다.
- 그러나 **사람이 육안으로 최종 대조·검수하는 화면을 제공할 때 치명적인 설계 결함 2가지**가 드러났다:
  1. **회전 결과 미저장**: 기계가 270도 돌려 판독했으면서 원본 파일은 누운 상태로 방치하고, 뷰어에서 또다시 CSS 회전 조작을 반복하게 만듦.
  2. **180도 상하반전 간과**: 카메라 촬영 각도에 따라 일부 사진은 180도 뒤집혀(주황색 스티커가 위, 검정 라벨이 아래로 거꾸로 위치) 있었음. 기계는 거꾸로 있어도 읽어내지만, **사람은 거꾸로 뒤집힌 텍스트를 정상적으로 읽지 못함**.

---

## 2. 배운 교훈 (Lessons Learned)

> **"기계가 읽을 수 있다고 해서 작업이 끝난 것이 아니다. 사람이 편안하게 인지할 수 있는 상태로 물리적 자산을 정돈하는 것까지가 시스템의 책임이다."**

1. **물리적 정방향 일괄 영구 저장**:
   - 임시 렌더링 회전(CSS Transform)에 의존하지 않고, 이미지 파일 자체를 사람이 편안히 읽을 수 있는 정방향(가로 책 읽기 방향)으로 디스크에 영구 갱신 저장해야 함.
2. **0° vs 180° 상하반전 2단계 인지 알고리즘**:
   - 90/270도 주파수 회전 판단 외에도, 라벨 내 텍스트 방향 점수(`score(0°) vs score(180°)`)를 비교하여 거꾸로 뒤집힌 사진을 완벽히 정방향(S/N 라벨이 상단, Windows 스티커가 하단)으로 뒤집어 주어야 함.
3. **인간-AI 협업(HITL) UI 비례 원칙**:
   - 육안 검수가 목적인 화면에서는 데이터 그리드가 아닌 **검수 대상 고해상도 이미지가 화면의 80%**를 차지해야 하며, 목록은 슬림 큐로 물러서야 함.
