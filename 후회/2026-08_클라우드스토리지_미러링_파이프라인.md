## 솔직한 회고 — 다시 한다면 무엇을 다르게 하겠는가

### 1. 원인 규명 전에 '임시 하드코딩(우회책)'을 절대 도입하지 말 것

- **문제**: Cloudflare Account ID 오타(...d74c1c... vs ...d74e1e...)로 S3 REST API 조회가 실패했을 때, 원인을 끝까지 추적하지 않고 '공개 URL + 정적 파일 목록(하드코딩)'이라는 임시 우회책을 작성했다.
- **결과**: 하드코딩에 없는 실제 파일(01~09번 파일) 누락, 빈 폴더 누락, 파일 확장 시 미러링 불능 등 연쇄적인 2차, 3차 결함이 발생하며 5회 이상의 무의미한 수정 반복을 초래했다.
- **교훈**: **'임시 땜질 코드는 기술 부채가 아니라 폭탄이다.'** 통신이 안 되면 식별자/자격증명과 네트워크 레벨의 근본 원인을 먼저 100% 규명해야 한다.

### 2. 구글 드라이브 유산을 '점진적 패치'가 아닌 '원스톱 전면 교체'로 처리했을 것

- **문제**: 구글 드라이브(Apps Script) 코드를 교체할 때 관련 파일(HTML 템플릿, 아카이브 폴더 생성기 등)을 한 번에 전수 조사하여 일괄 파기하지 않고 발견될 때마다 부분 수정했다.
- **결과**: archive/ 폴더 잔재, GAS 웹훅 템플릿 잔재가 남아 사용자에게 지속적인 혼란과 불신을 안겼다.
- **교훈**: 아키텍처 전환 시에는 영향받는 전사 파일 트리를 먼저 전수 Grep하여 단 한 번의 커밋으로 잔재를 100% 발본색원해야 한다.

### 3. 단방향 동기화 주체(SSOT)를 처음부터 '에이전트 자가 풀(Pull)'로 단일화했을 것

- **문제**: '프런트엔드가 브라우저에서 다운로드 후 에이전트에 POST 푸시'하는 방식과 '에이전트가 직접 당겨오는 방식'이 혼재하여, 브라우저 새로고침(F5) 시점이나 에이전트 단독 기동 시점마다 동기화 결과가 달라졌다.
- **결과**: 'F5를 했는데 왜 미러링이 안 되느냐', '에이전트를 켰는데 왜 파일이 없느냐'는 질문이 반복되었다.
- **교훈**: 미러링의 주체는 항상 데이터를 보관하는 **로컬 에이전트 단독 자립 풀(Pull) 구조**여야 하며, 프런트엔드는 트리거 및 모니터링 역할만 담당해야 한다.

## 이 후회가 주는 시스템 설계 원칙

> **'100% 동적 실시간 스캔과 Zero-Dependency 자립성만이 영구적인 무인화를 보장한다.'**

- 어떠한 파일명, 폴더명도 코드 내에 하드코딩하지 않는다.
- 외부 무거운 npm 라이브러리에 기대지 않고 Node.js 내장 모듈(SigV4)로 자립 구동하도록 설계한다.
- 파일뿐만 아니라 디렉토리 마커(빈 폴더)까지 클라우드 스토리지 표준 규격을 완벽히 준수한다.
