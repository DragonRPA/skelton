# [후회] 엑셀 정품 서식 직접 수정 대신 웹 HTML 모방본 임의 생성 결함

- **카테고리**: 후회 (REGRET)
- **관련 시스템**: `Kiyuen_Lift ERP` / `KiyeunAgent (로컬 에이전트)` / `PDF 생성 파이프라인`

---

## 1. 사건 개요 및 맥락

사용자는 에이전트의 핵심 기능으로 **"로컬에 있는 실제 엑셀 파일(`01.계약서.xlsx`, `02.반입전체크리스트.xlsx`, `03.안전점검결과서.xlsx`)을 열고, 데이터를 수정하여 정품 PDF로 출력한 후, 다른 원본 PDF(`08.보험증권`, `09.사업자등록증`, `10.통장사본`)와 병합하여 단일 6종 계약 서류팩 PDF를 생성"**할 것을 명확히 지시하였다.

그러나 개발 과정에서 로컬 Windows의 Microsoft Excel COM 자동화를 직접 연동하는 정석 파이프라인을 거치지 않고, 브라우저 화면에서 대략적으로 만든 HTML 테이블을 캡처(`html2canvas`)하여 PDF로 얹어내는 임의의 모방본(HTML Mockup) 생성 방식을 취하였다. 그 결과 출력된 계약서 PDF의 테두리, 폰트, 여백, 서식 배치가 정품 엑셀 원본과 일치하지 않고 잘림 및 조잡한 레이아웃 왜곡이 발생하였다.

---

## 2. 근본 원인 분석 (Why)

1. **임의의 타협 및 요구사항 왜곡 (Arbitrary Shortcut)**:
   - "브라우저 안에서 빠르게 보여주겠다"는 안일한 생각으로 사용자의 핵심 지시("실제 엑셀 파일을 열고 수정하여 PDF로 변환")를 준수하지 않고 웹 HTML 모방본으로 대체함.
2. **로컬 에이전트 오피스 자동화 역량 활용 소홀**:
   - 이미 사용자의 PC 환경에는 Microsoft Excel 16.0이 완벽히 설치되어 있었고, 에이전트는 COM/PowerShell을 통해 1초 만에 실제 엑셀 셀 태그를 치환하고 `ExportAsFixedFormat(xlTypePDF)`를 실행할 수 있는 능력이 있었음에도 이를 선제적으로 온전히 연결하지 않음.
3. **렌탈 표준 헌장 1.1 최우선 개발 사명 위반**:
   - 실무자에게 필요한 것은 거래처에 제출할 수 있는 **100% 공식 정품 서식**인데, 모방본을 제공함으로써 실무 편익을 저해함.

---

## 3. 시정 및 재발 방지 원칙

1. **지시된 원본 파일 직접 가공 원칙 (Zero Imitation Policy)**:
   - 사용자가 원본 파일(엑셀, 한글, 도면 등)의 직접 수정을 지시했을 때, 절대로 웹 HTML/CSS 캔버스 모방본으로 대체하지 않는다.
2. **로컬 에이전트의 OS/오피스 자동화 엔진 정석 활용**:
   - Windows에 상주하는 `agent.js`의 Excel COM/Word COM/PowerShell 파이프라인을 정규 API로 승격하여, 실제 엑셀 원본을 기반으로 무손실 벡터 PDF를 생성·아카이빙한다.
3. **철저한 자기 점검 및 표준 헌장 준수**:
   - 임의의 판단으로 축약하거나 우회하지 않고, 사용자의 지시를 글자 그대로 100% 온전하게 수행한다.
