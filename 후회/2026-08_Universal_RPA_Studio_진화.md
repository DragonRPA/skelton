## 후회 1: `python -c "..."` 인라인 실행 반복 시도

**상황**: PowerShell에서 `python -c "..."` 방식으로 한글 포함 코드를 반복 실행 시도
**결과**: cp949 인코딩 오류, 따옴표 이스케이프 충돌로 매번 실패
**피해**: 디버깅 시간 낭비, 같은 실수를 3회 이상 반복
**교훈**: 한 번만 파일로 저장하고 `& python script.py`로 실행하면 됐다
**재발 방지**: `python -c` 방식은 영구 금지. 항상 `.py` 파일로 저장 후 실행.

## 후회 2: 정규식 패치 스크립트의 docstring 파괴

**상황**: 여러 함수 docstring과 코드를 한번에 교체하려 `re.sub()` 스크립트 사용
**결과**: `"""docstring"""        코드` 형태로 합쳐지는 파괴적 오류 발생
**피해**: 파일 전체 IndentationError, 클래스 수준 docstring까지 피해
**복구**: `git checkout HEAD -- ai_vision_agent.py` 로 복원 후 `replace_file_content` 재패치
**교훈**: Python 소스 패치에 정규식은 위험하다. AST 파싱 또는 정확한 문자열 replace만 사용
**재발 방지**: 패치 스크립트는 항상 `TargetContent`를 파일에서 직접 복사해서 exact match 보장

## 후회 3: 바로가기 속성 변경 미검증

**상황**: CDP 브라우저 바로가기를 새로 만들었다고 보고했으나 속성이 이전과 동일
**결과**: 사용자가 직접 비교해서 변경사항이 없음을 발견
**교훈**: 파일/설정 변경 후 실제로 달라진 것을 diff 또는 직접 확인해서 보고해야 함
**재발 방지**: 바로가기/설정 파일 변경 시 Before/After 속성을 출력해서 검증

---

## 후회 4: 패치 후 즉시 구문 검사 미이행

**상황**: 패치 완료 보고 후 구문 검사 없이 다음 단계 진행
**결과**: IndentationError가 누적되어 나중에 복합 오류로 발견
**교훈**: 모든 .py 파일 수정 후 즉시 `python -m py_compile` 검사가 필수
**재발 방지**: 패치 스크립트 마지막 단계에 반드시 구문 검사 포함

---

## 후회 5: 브라우저 UI 제거 시 참조 코드 미정리

**상황**: `seg_browser.get()` 참조를 삭제하지 않고 하드코딩 "Chrome"으로만 교체
**결과**: 이후 다른 브라우저 관련 참조가 남아 잠재적 오류 위험
**교훈**: UI 컴포넌트 제거 시 해당 컴포넌트를 참조하는 모든 코드를 grep으로 확인 후 일괄 제거
